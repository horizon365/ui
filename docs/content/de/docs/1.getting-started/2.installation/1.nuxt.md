## setup (englisch)

### Zu einem Nuxt-Projekt hinzufügen

::steps{level="4"}

#### Installieren Sie das Nuxt-UI-Paket

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Füge das Nuxt UI-Modul in deinem `nuxt.config.ts`{lang="ts-type"} hinzu.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui']
})
```

::note
Es ist nicht notwendig, `@nuxt/icon`, `@nuxt/fonts` oder `@nuxtjs/color-mode` zu Ihrem `modules`-Array hinzuzufügen, da Nuxt UI sie automatisch registriert.
::

#### Importieren Sie Tailwind CSS und Nuxt UI in Ihr CSS

::code-group

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
```

```ts [nuxt.config.ts] {3}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css']
})
```

::

::tip{to="https://nuxt.com/docs/getting-started/layers" target="_blank"}
Wenn Sie [Nuxt Layers](https://nuxt.com/docs/getting-started/layers) verwenden, generiert das Modul automatisch [`@source`](https://tailwindcss.com/docs/functions-and-directives#source-directive)-Direktiven für jedes Layer-Verzeichnis, um sicherzustellen, dass Tailwind CSS alle Layer-Quelldateien nach Utility-Klassen durchsucht.
::

::callout{icon="i-simple-icons-visualstudiocode"}
Es wird empfohlen, die [Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) Erweiterung für VSCode zu installieren und folgende Einstellungen hinzuzufügen:

```json [.vscode/settings.json]
{
  "files.associations": {
    "*.css": "tailwindcss"
  },
  "editor.quickSuggestions": {
    "strings": "on"
  },
  "tailwindCSS.classAttributes": ["class", "ui"],
  "tailwindCSS.classFunctions": ["defineAppConfig"]
}
```

::

#### Wickeln Sie Ihre App mit App-Komponente

```vue [app.vue]
<template>
  <UApp>
    <NuxtPage />
  </UApp>
</template>
```

::note{to="/docs/components/app"}
Die `App`-Komponente richtet die globale Konfiguration ein und wird für **Toast**, **Tooltip** und **programmatic overlays** benötigt.
::

::

## Options (englisch)

Sie können Nuxt UI anpassen, indem Sie Optionen in Ihrem `nuxt.config.ts` bereitstellen.

### `prefix` (nicht)

Verwenden Sie die Option `prefix`, um den Präfix der Komponenten zu ändern.

- Default: `U`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    prefix: 'Nuxt'
  }
})
```

### `fonts` nicht

Verwenden Sie die `fonts`-Option, um das [`@nuxt/fonts`](https://github.com/nuxt/fonts)-Modul zu aktivieren oder zu deaktivieren.

- Standard: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    fonts: false
  }
})
```

### `colorMode` Übersetzung

Verwenden Sie die `colorMode`-Option, um das Modul [`@nuxt/color-mode`](https://github.com/nuxt-modules/color-mode) zu aktivieren oder zu deaktivieren.

- Standard: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    colorMode: false
  }
})
```

### `theme.colors` Übersetzung

Verwenden Sie die `theme.colors`-Option, um die dynamischen Farbaliase zu definieren, die zum Generieren des Komponentendesigns verwendet werden.

- Standard: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      colors: ['primary', 'error']
    }
  }
})
```

::note
Jeder Alias generiert einen vollständigen Satz von `--ui-color-*`-Schattierungen und-Varianten in den Komponententhemen mit Farbvarianten, unabhängig davon, ob Ihre App sie verwendet oder nicht. Trimmen Sie die Liste auf die tatsächlich verwendeten Aliase und behalten Sie `error` bei, wenn Sie Formulare verwenden, da Validierungsstile darauf angewiesen sind.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Erfahren Sie mehr über die Farbanpassung und das Thema im Themenbereich.
::

### `theme.transitions` Übersetzung

Verwenden Sie die `theme.transitions`-Option, um Übergänge auf Komponenten zu aktivieren oder zu deaktivieren.

- Standard: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      transitions: false
    }
  }
})
```

::note
Diese Option fügt die `transition-colors`-Klasse für Komponenten mit hover-oder aktiven Zuständen hinzu.
::

### `theme.unstyled`: badge{label="4.9+" class="align-text-top"} (englisch)

Verwenden Sie die Option `theme.unstyled`, um alle Standardtheme-Klassen aus Komponenten zu entfernen und nur deren Struktur und die Klassen beizubehalten, die Sie über `class`, `ui` oder `app.config.ui` bereitstellen.

- Standard: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      unstyled: true
    }
  }
})
```

::warning
Dies entfernt auch **structural**-Klassen (Positionierung, Übergänge, Flex/Grid), nicht nur kosmetische. Layout-schwere Komponenten wie `Modal`, `Drawer` oder `Calendar` müssen Sie ihr Layout erneut bereitstellen, ähnlich wie im unstyled mode von PrimeVue.
::

### `theme.defaultVariants` Bearbeiten

Verwenden Sie die Option `theme.defaultVariants`, um die Standardvarianten `color` und `size` für Komponenten außer Kraft zu setzen.

Nur Standardwerte, die genau `primary` oder `md` sind, werden ersetzt, sodass Avatar `color: 'neutral'` und Separator `size: 'xs'` behält.

- Standard: `{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [nuxt.config.ts] {4-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      defaultVariants: {
        color: 'neutral',
        size: 'sm'
      }
    }
  }
})
```

### `theme.prefix`: badge{label="4.2+" class="align-text-top"} (englisch)

Verwenden Sie die Option `theme.prefix`, um das gleiche Präfix zu konfigurieren, das Sie beim Tailwind CSS-Import festgelegt haben. Dadurch wird sichergestellt, dass die Nuxt-UI-Komponenten die richtigen vordefinierten Hilfsklassen und CSS-Variablen verwenden.

::code-group

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  }
})
```

```css [app/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

::warning{to="https://fonts.nuxt.com/get-started/configuration#processcssvariables"}
Möglicherweise müssen Sie `fonts.processCSSVariables` aktivieren, um die Präfixoption mit dem `@nuxt/fonts`-Modul zu verwenden:

```ts [nuxt.config.ts] {9-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  },
  fonts: {
    processCSSVariables: true
  }
})
```
::

Dadurch werden automatisch alle Tailwind-Utility-Klassen und CSS-Variablen in Nuxt UI-Komponententhemen vorangestellt:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Weitere Informationen zur Verwendung eines Präfixes finden Sie in der Tailwind CSS-Dokumentation.
::

### `prose` nicht

Verwenden Sie die `prose`-Option, um den Import von Nuxt UI [`Prose` components](/docs/typography) zu erzwingen, auch wenn `@nuxtjs/mdc`, `@nuxt/content` oder `@comark/nuxt` nicht installiert ist.

- Standard: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    prose: true
  }
})
```

### `mdc`: badge{label="Deprecated" color="warning" class="align-text-top"} (englisch)

Verwenden Sie stattdessen die [`prose`](#prose)-Option.

### `content` nicht

Verwenden Sie die Option `content`, um den Import der Nuxt UI-Prosa-und Inhaltskomponenten zu erzwingen, auch wenn `@nuxt/content` nicht installiert ist.

- Default: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    content: true
  }
})
```

### `experimental.componentDetection`: badge{label="4.1+" class="align-text-top"} (englisch)

Diese Funktion scannt Ihren Quellcode, um zu erkennen, welche Komponenten tatsächlich verwendet werden, und generiert nur das erforderliche CSS für diese Komponenten (einschließlich ihrer Abhängigkeiten).

- Standard: `false`{lang="ts-type"}
- Type: `boolean | string[]`{lang="ts-type"} (englisch)

**Enable automatische Erkennung: **

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: true
    }
  }
})
```

**Fügen Sie zusätzliche Komponenten für die dynamische Nutzung hinzu: **

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: ['Modal', 'DropdownMenu', 'Popover']
    }
  }
})
```

::note
Bei der Bereitstellung eines Arrays von Komponentennamen ist die automatische Erkennung aktiviert und diese Komponenten (zusammen mit ihren Abhängigkeiten) werden garantiert einbezogen. Dies ist nützlich für dynamische Komponenten wie `<component :is="..." />`, die nicht statisch analysiert werden können.
::

## Continuous Releases (Kontinuierliche Releases)

Die Benutzeroberfläche von Nuxt verwendet [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new) für kontinuierliche Vorschauversionen und bietet Entwicklern sofortigen Zugriff auf die neuesten Funktionen und Fehlerbehebungen, ohne auf offizielle Veröffentlichungen warten zu müssen.

Automatische Vorschau-Releases werden für alle Commits und PRs im `v4`-Zweig erstellt. Verwenden Sie sie, indem Sie Ihre Paketversion durch den spezifischen Commit-Hash oder die PR-Nummer ersetzen.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new** kommentiert PRs automatisch mit der Installations-URL, sodass Änderungen einfach getestet werden können.
::
