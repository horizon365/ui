## setup (englisch)

### Zu einem Vue-Projekt hinzufügen

::steps{level="4"}

#### Installieren Sie das Nuxt-UI-Paket

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Add the Nuxt UI Vite plugin in your `vite.config.ts`{lang="ts-type"} Füge das Nuxt UI Vite Plugin in deinem `vite.config.ts`{lang="ts-type"} hinzu

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI registriert `unplugin-auto-import` und `unplugin-vue-components`, die `auto-imports.d.ts` und `components.d.ts` Typdeklarationsdateien generieren.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
Diese Deklarationsdateien werden nur geschrieben, wenn Vite ausgeführt wird. Das Standardskript `create-vue` `build` führt `vue-tsc` parallel zu `vite build` (`run-p type-check "build-only {@}"`) aus, so dass bei einem sauberen Checkout die Typprüfung beginnen kann, bevor die Dateien vorhanden sind, und mit Fehlern wie `Cannot find name 'useToast'` fehlschlägt.

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
Wenn Sie TypeScript verwenden, fügen Sie diese Aliase Ihren `tsconfig`-Dateien hinzu, um die automatische Vervollständigung in Ihrem `vite.config.ts` zu aktivieren.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```
::

#### Verwenden Sie das Nuxt UI Vue-Plugin

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

```ts [inertia/app/app.ts (AdonisJS Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'

})
```

#### Fügen Sie die `isolate`-Klasse zu Ihrem Root-Container hinzu

::code-group{sync="vite"}

```html [index.html (Vite)]{9}
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Nuxt UI</title>
  </head>
  <body>
    <div id="app" class="isolate"></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

```blade [resources/views/app.blade.php (Laravel Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">
    @inertiaHead
    @vite('resources/js/app.ts')
  </head>
  <body>
    <div class="isolate">
        @inertia
    </div>
  </body>
</html>
```

```edge [resources/views/inertia_layout.edge (AdonisJS Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">
    @inertiaHead()
    @vite(['inertia/app/app.ts', `inertia/pages/${page.component}.vue`])
  </head>
  <body>
    @inertia({ class: 'isolate' })
  </body>
</html>
```

::

::note
Dadurch wird sichergestellt, dass Stile auf Ihre App abgestimmt sind, und Probleme mit Overlays und Stapelkontexten werden vermieden.

## Options (englisch)

Sie können die Nuxt-Benutzeroberfläche anpassen, indem Sie Optionen in Ihrem `vite.config.ts` bereitstellen.

### `prefix` nicht

Verwenden Sie die Option `prefix`, um das Präfix der Komponenten zu ändern.

- Standard: `U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

### `ui` nicht

Verwenden Sie die Option `ui`, um die Konfiguration für die Nuxt-Benutzeroberfläche bereitzustellen. Dies ist das Vue-Äquivalent des `ui`-Schlüssels in Nuxts `app.config.ts`.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

### `dts` nicht

Verwenden Sie die Option `dts`, um die Erzeugung von Deklarationsdateien für automatisch importierte Komponenten und Compositables zu aktivieren oder zu deaktivieren.

- Default: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

### x`icon`

Verwenden Sie die `icon`-Option, um Standard-Requisiten für die Komponente [Icon](/docs/components/icon) (`size`, `mode`, `customize`) festzulegen und die Bündelung von Build-Time-Icons über `clientBundle` zu konfigurieren.

- Standard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
Weitere Informationen zu Icon-Sammlungen und Client-Bündelung finden Sie in der Dokumentation **Icons**.
::

### `colorMode` nicht

Verwenden Sie die `colorMode`-Option, um die Farbmodusintegration von `@vueuse/core` zu aktivieren oder zu deaktivieren.

- Standard: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

### `theme.colors` nicht

Verwenden Sie die Option `theme.colors`, um die dynamischen Farbaliase zu definieren, die zum Generieren des Komponentendesigns verwendet werden.

- Standard: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Jeder Alias generiert einen vollständigen Satz von `--ui-color-*`-Schattierungen und-Varianten in den Komponententhemen mit Farbvarianten, unabhängig davon, ob Ihre App sie verwendet oder nicht. Trimmen Sie die Liste auf die tatsächlich verwendeten Aliase und behalten Sie `error` bei, wenn Sie Formulare verwenden, da Validierungsstile darauf angewiesen sind.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Erfahren Sie mehr über die Farbanpassung und das Thema im Themenbereich.
::

### `theme.transitions` (nicht)

Verwenden Sie die `theme.transitions`-Option, um Übergänge auf Komponenten zu aktivieren oder zu deaktivieren.

- Standard: `true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
Diese Option fügt die `transition-colors`-Klasse für Komponenten mit hover-oder aktiven Zuständen hinzu.
::

### `theme.unstyled`: badge{label="4.9+" class="align-text-top"} (englisch)

Verwenden Sie die Option `theme.unstyled`, um alle Standardthemenklassen aus Komponenten zu entfernen und nur deren Struktur und die Klassen beizubehalten, die Sie über `class`, `ui` oder `app.config.ui` bereitstellen.

- Default: `false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Dies entfernt auch **structural**-Klassen (Positionierung, Übergänge, Flex/Grid), nicht nur kosmetische. Layout-schwere Komponenten wie `Modal`, `Drawer` oder `Calendar` müssen Sie ihr Layout neu liefern, ähnlich wie im unstyled mode von PrimeVue.
::

### `theme.defaultVariants` (englisch)

Verwenden Sie die Option `theme.defaultVariants`, um die Standardvarianten `color` und `size` für Komponenten außer Kraft zu setzen.

Nur Standardwerte, die genau `primary` oder `md` sind, werden ersetzt, sodass Avatar `color: 'neutral'` und Separator `size: 'xs'` behält.

- Standard: `{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix`: badge{label="4.2+" class="align-text-top"} (Deutsche Übersetzung)

Verwenden Sie die Option `theme.prefix`, um das gleiche Präfix zu konfigurieren, das Sie beim Tailwind CSS-Import festgelegt haben. Dadurch wird sichergestellt, dass die Nuxt-UI-Komponenten die richtigen vordefinierten Hilfsklassen und CSS-Variablen verwenden.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Dadurch werden automatisch alle Tailwind-Utility-Klassen und CSS-Variablen in Nuxt UI-Komponententhemen vorangestellt:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Weitere Informationen zur Verwendung eines Präfixes finden Sie in der Tailwind CSS-Dokumentation.
::

### `prose` nicht

Verwenden Sie die `prose`-Option, um die Nuxt-Benutzeroberfläche [`Prose` components](/docs/typography) und ihr Design zu aktivieren.

- Standard: `false`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prose: true
    })
  ]
})
```

### `autoImport` (englisch)

Verwenden Sie die `autoImport`-Option, um den automatischen Import von Composable zu deaktivieren oder die [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import)-Optionen anzupassen.

- Standard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      autoImport: false
    })
  ]
})
```

::note
Wenn diese Option deaktiviert ist, können Sie Compositables weiterhin explizit aus `@nuxt/ui/composables` importieren.
::

### x`components`

Verwenden Sie die `components`-Option, um den automatischen Import von Komponenten zu deaktivieren oder die [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components)-Optionen anzupassen.

- Standard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      components: false
    })
  ]
})
```

::note
Wenn deaktiviert, können Sie weiterhin Komponenten explizit importieren, z. B. `import Button from '@nuxt/ui/components/Button.vue'` oder `import ProseCode from '@nuxt/ui/components/prose/Code.vue'`.
::

### `router`: badge{label="4.3+" class="align-text-top"} (Deutsche Übersetzung)

Dies ist nützlich für Anwendungen, die `vue-router` nicht verwenden, z. B. Electron-Apps, MPAs oder Frameworks wie [Inertia.js](https://inertiajs.com/) oder [Hybridly](https://hybridly.dev/xph75x.

- Standard: `true`{lang="ts-type"}

| Wert| Description|
| ----- | ----------- |
| `true`{lang="ts-type"} nicht| Verwendet `vue-router` für die Navigation mit der `RouterLink`-Komponente.|
| `false`{lang="ts-type"} Übersetzung| Deaktiviert Routing-Integration, Links werden als einfache `<a>`-Tags gerendert.|
| `'inertia'`{lang="ts-type"} Übersetzung| Verwendet Inertia.js für die Navigation mit seiner `Link` Komponente.|

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
Sie können benutzerdefinierte Navigationslogik für Frameworks wie **Hybridly** bereitstellen, indem Sie `router: false` in der Vite Config festlegen und bei der Installation des Vue-Plugins eine Funktion übergeben:

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
Wenn `false` oder `'inertia'` eingestellt ist, ist `vue-router` nicht als Abhängigkeit erforderlich.
::

### `scanPackages`: badge{label="4.3+" class="align-text-top"} (englisch)

Verwenden Sie die Option `scanPackages`, um zusätzliche npm-Pakete anzugeben, die mithilfe der Nuxt-Benutzeroberfläche nach Komponenten durchsucht werden sollen.

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
Standardmäßig wird nur `@nuxt/ui` gescannt. Verwenden Sie diese Option, wenn Ihre externen Pakete Vue-Komponenten enthalten, die Nuxt-Benutzeroberfläche verwenden.
::

### `root`: badge{label="4.9+" class="align-text-top"} (englisch)

Verwenden Sie die `root`-Option, um das Verzeichnis zu überschreiben, in dem Nuxt UI sein `.nuxt-ui`-Verzeichnis generiert Standardmäßig verwendet es Vite's `root`, aber in Setups wie [`electron-vite`](https://electron-vite.org/) zeigt der Renderer `root` auf ein Unterverzeichnis.(z.B. `src/renderer`), so dass die Vorlagen in `src/renderer/node_modules/.nuxt-ui` landen, wo Tailwind sie nicht scannt, was dazu führt, dass Theme-Klassen wie `bg-default`, `ring-default` und `divide-default` fehlen.

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Zeigen Sie `root` auf Ihren Projektstamm, damit das generierte `.nuxt-ui`-Verzeichnis in einem `node_modules` endet, das Tailwind scannt.
::

### `experimental.componentDetection`: badge{label="4.11+" class="align-text-top"} (englisch)

Verwenden Sie die Option `experimental.componentDetection`, um die automatische Komponentenerkennung für Baumschütteln zu aktivieren. Diese Funktion scannt Ihren Quellcode, um zu erkennen, welche Komponenten tatsächlich verwendet werden, und generiert nur das erforderliche CSS für diese Komponenten.(einschließlich ihrer Abhängigkeiten). Ohne sie, die Vite Plugin generiert das Thema CSS für jede Komponente. Detection deckt die Vite Wurzel, die Pakete, die in [`scanPackages`](#scanpackages) aufgeführt sind, und jedes `dirs` von der [`components`](#components) Option, die sich außerhalb des Root befindet.

- Standard: `false`{lang="ts-type"}
- Type: `boolean | string[]`{lang="ts-type"} (englisch)

**Automatische Erkennung aktivieren: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**Fügen Sie zusätzliche Komponenten für die dynamische Verwendung hinzu: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Wenn Sie ein Array von Komponentennamen bereitstellen, wird die automatische Erkennung aktiviert und diese Komponenten (zusammen mit ihren Abhängigkeiten) werden garantiert einbezogen. Dies ist nützlich für dynamische Komponenten wie `<component :is="..." />`, die nicht statisch analysiert werden können.
::

::warning
Neu verwendete Komponenten werden beim nächsten Start des Dev-Servers aufgenommen. Wenn Sie eine Komponente hinzufügen und deren Stile fehlen, starten Sie den Dev-Server neu.
::

## Continuous Releases veröffentlicht

Die Benutzeroberfläche von Nuxt verwendet [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new) für kontinuierliche Vorschauversionen und bietet Entwicklern sofortigen Zugriff auf die neuesten Funktionen und Fehlerbehebungen, ohne auf offizielle Veröffentlichungen warten zu müssen.

Automatische Vorschau-Releases werden für alle Commits und PRs im `v4`-Branch erstellt. Verwenden Sie sie, indem Sie Ihre Paketversion durch den spezifischen Commit-Hash oder die PR-Nummer ersetzen.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new** kommentiert PRs automatisch mit der Installations-URL, so dass Änderungen einfach getestet werden können.
::
