### Hinzufügen zu einem Vue-Projekt

::steps{level="4"}

#### Install das Nuxt UI Paket installieren

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

#### Füge das Nuxt UI Vite Plugin in dein`vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI registriert`unplugin-auto-import`und`unplugin-vue-components`, wodurch die Deklarationsdateien`auto-imports.d.ts`und`components.d.ts`generiert werden .

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
Das Standard-Skript`create-vue``build`läuft parallel zu`vite build`(`run-p type-check "build-only {@}"`) , so dass bei einem sauberen Checkout die Typprüfung beginnen kann , bevor die Dateien existieren und mit Fehlern wie`Cannot find name 'useToast'`fehlschlagen kann .

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
Wenn Sie TypeScript verwenden , fügen Sie diese Aliase zu Ihren`tsconfig`- Dateien hinzu , um die automatische Vervollständigung in Ihrem`vite.config.ts`zu aktivieren .

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```

#### Verwenden Sie das Nuxt UI Vue Plugin

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

@@ph387@Optionen

Sie können die Nuxt-Benutzeroberfläche anpassen , indem Sie Optionen in Ihrem`vite.config.ts`angeben .

`prefix`

Verwenden Sie die Option `prefix`, um das Präfix für die Komponenten zu ändern.

- Default:`U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@########################################################################################################################

Verwenden Sie die Option `ui`, um die Konfiguration für die Nuxt-Benutzeroberfläche bereitzustellen. Dies ist das Vue-Äquivalent des Schlüssels `ui` in Nuxts `app.config.ts`.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

`dts`

Verwenden Sie die Option `dts`, um die Erzeugung von Deklarationsdateien für automatisch importierte Komponenten und Compositables zu aktivieren oder zu deaktivieren.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

`icon`

Verwenden Sie die Option `icon`, um Standard-Requisiten für die Komponente [Icon](/docs/components/icon) festzulegen.`size`,`mode`,`size`,`mode`,`mode`,`mode`,`mode`,`mode`,`size`,`mode`,`mode`,`mode`,`mode``customize`) und zur Konfiguration der Build-Time-Symbolbündelung über `clientBundle`. Das Bündeln der eigenen Symbole von Nuxt UI ist standardmäßig aktiviert, wenn ihre Sammlung installiert ist. Set`clientBundle: false` zum Ausschalten.

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
Weitere Informationen zu Icon-Sammlungen und Client-Bündelung finden Sie in der Dokumentation **Icons**.
::

`colorMode`

Verwenden Sie die Option `colorMode`, um die Farbmodus-Integration von `@vueuse/core` zu aktivieren oder zu deaktivieren.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

`theme.colors`

Verwenden Sie die Option `theme.colors`, um die dynamischen Farbaliase zu definieren, die zum Generieren des Komponentendesigns verwendet werden.

- Default:`['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Jeder Alias generiert einen vollständigen Satz von `--ui-color-*` Schattierungen und Varianten in den Komponententhemen mit Farbvarianten, unabhängig davon, ob Ihre App sie verwendet oder nicht. Trimmen Sie die Liste auf die Aliase, die Sie tatsächlich verwenden, und behalten Sie `error`, wenn Sie Formulare verwenden, da Validierungsstile darauf angewiesen sind.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Erfahren Sie mehr über die Farbanpassung und das Thema im Themenbereich.
::

`theme.transitions`

Verwenden Sie die Option `theme.transitions`, um Übergänge an Komponenten zu aktivieren oder zu deaktivieren.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
Mit dieser Option wird die Klasse `transition-colors` für Komponenten mit hover-oder aktivem Status hinzugefügt.
::

`theme.unstyled`: badge{label="4.9+" class="align-text-top"}

Verwenden Sie die Option `theme.unstyled`, um alle Standardthemenklassen aus Komponenten zu entfernen und nur deren Struktur und die Klassen beizubehalten, die Sie über `class`,`ui` oder `app.config.ui` bereitstellen.

- Default:`false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Dies streift auch **struktural** Klassen (Positionierung, Übergänge, Flex/Grid), nicht nur kosmetische. Layout-schwere Komponenten wie `Modal`,`Drawer` oder `Calendar` müssen Sie ihr Layout ähnlich dem unstyled Modus von PrimeVue erneut liefern.
::

`theme.defaultVariants`

Verwenden Sie die Option `theme.defaultVariants`, um die Standardvarianten `color` und `size` für Komponenten zu überschreiben.

Nur Standardwerte, die genau `primary` oder `md` sind, werden ersetzt, so dass Avatar `color: 'neutral'` und Separator `size: 'xs'` behält.

@@@597`{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

`theme.prefix`: badge{label="4.2+" class="align-text-top"}

Verwenden Sie die `theme.prefix`-Option, um das gleiche Präfix zu konfigurieren, das Sie für Ihren Tailwind CSS-Import festgelegt haben. Dadurch wird sichergestellt, dass Nuxt-UI-Komponenten die richtigen vordefinierten Hilfsklassen und CSS-Variablen verwenden.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Dadurch werden automatisch alle Tailwind-Utility-Klassen und CSS-Variablen in Nuxt UI-Komponententhemen vorangestellt:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Weitere Informationen zur Verwendung eines Präfixes finden Sie in der Tailwind CSS-Dokumentation.
::

Verwenden Sie die Option `prose`, um Nuxt UI [`Prose` components](/docs/typography) und deren Thema zu aktivieren.

- Default:`false`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prose: true
    })
  ]
})
```

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

Verwenden Sie die Option `autoImport`, um den automatischen Import von Komponenten zu deaktivieren oder um die Optionen [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import) anzupassen.

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      autoImport: false
    })
  ]
})
```

::note
Wenn Sie deaktiviert sind, können Sie Compositables weiterhin explizit aus `@nuxt/ui/composables` importieren.
::

Verwenden Sie die Option `components`, um den automatischen Import von Komponenten zu deaktivieren oder um die Optionen [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components) anzupassen.

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      components: false
    })
  ]
})
```

::note
Wenn deaktiviert, können Sie Komponenten weiterhin explizit importieren, z. B.`import Button from '@nuxt/ui/components/Button.vue'` oder `import ProseCode from '@nuxt/ui/components/prose/Code.vue'`.
::

`scanPackages`:

Verwenden Sie die Option`scanPackages`, um zusätzliche npm-Pakete anzugeben , die mithilfe der Nuxt-Benutzeroberfläche nach Komponenten durchsucht werden sollen .

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

    vue(),
    ui({
```

`root`: badge{label="4.9+" class="align-text-top"}

Verwenden Sie die Option`root`, um das Verzeichnis zu überschreiben , in dem Nuxt UI sein`.nuxt-ui`- Verzeichnis erzeugt .(enthält die Theme-Vorlagen) . By default verwendet es Vite 's`root`, aber in Setups wie[`electron-vite`](https://electron-vite.org/)zeigt der Renderer`root`auf ein Unterverzeichnis (z.B.`src/renderer`) , so dass die Vorlagen in`src/renderer/node_modules/.nuxt-ui`landen , wo Tailwind sie nicht scannt , wodurch Theme-Klassen wie`bg-default`,`ring-default`und`divide-default`fehlen .

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Zeigen Sie`root`an Ihren Projektstamm , so dass das generierte Verzeichnis`.nuxt-ui`in einem`node_modules`endet , das Tailwind scannt .
::

`experimental.componentDetection`: badge{label="4.11+" class="align-text-top"}

Verwenden Sie die Option`experimental.componentDetection`, um die automatische Komponentenerkennung für das Baumschütteln zu aktivieren . Diese Funktion scannt Ihren Quellcode , um festzustellen , welche Komponenten tatsächlich verwendet werden , und generiert nur das erforderliche CSS für diese Komponenten .(einschließlich ihrer Abhängigkeiten) . Ohne sie , die Vite Plugin generiert das Thema CSS für jede Komponente . Detection deckt die Vite Wurzel , die Pakete , die in[`scanPackages`]()und alle`dirs`von der Option[`components`](#components)aufgelistet sind , die sich außerhalb der Wurzel befinden .

@@@861`false`{lang="ts-type"}
@@@864`boolean | string[]`{lang="ts-type"}

**Aktivieren der automatischen Erkennung :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**Include zusätzliche Komponenten für die dynamische Nutzung :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Bei der Bereitstellung eines Arrays von Komponentennamen wird die automatische Erkennung aktiviert und diese Komponenten (zusammen mit ihren Abhängigkeiten) werden garantiert einbezogen . Dies ist nützlich für dynamische Komponenten wie`<component :is="..." />`, die nicht statisch analysiert werden können .
::

::warning
Neu verwendete Komponenten werden beim nächsten Start des Dev-Servers übernommen . Wenn Sie eine Komponente hinzufügen und deren Stile fehlen , starten Sie den Dev-Server neu .
::

## Fortlaufende Veröffentlichungen

Nuxt UI verwendet[pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)für kontinuierliche Vorschauversionen , die Entwicklern sofortigen Zugriff auf die neuesten Funktionen und Fehlerbehebungen bieten , ohne auf offizielle Veröffentlichungen warten zu müssen .

Automatische Vorschau-Releases werden für alle Commits und PRs an den`v4`branch . Use erstellt , indem Sie Ihre Paketversion durch den spezifischen Commit-Hash oder die PR-Nummer ersetzen .

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
@@@@@@@@@918pkg.pr.new**kommentiert PRs automatisch mit der Installations-URL , sodass Änderungen einfach getestet werden können .
::
