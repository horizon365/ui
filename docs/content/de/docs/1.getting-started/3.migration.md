Nuxt UI v4 markiert einen wichtigen Meilenstein: **Nuxt UI und Nuxt UI Pro sind jetzt in einer einzigen, vollständig quelloffenen und kostenlosen Bibliothek vereint **.

::note
Nuxt UI v4 benötigt **Nuxt 4.1 oder später ** aufgrund einiger Abhängigkeiten.
::

Dieses Handbuch enthält eine Schritt-für-Schritt-Anleitung zum Migrieren Ihrer Anwendung von v3 nach v4.

## Migrate Ihr Projekt

### Von Nuxt UI Pro

1. `@nuxt/ui-pro` mit `@nuxt/ui` in Ihrem `package.json`:

::code-group{sync="pm"}

```bash [pnpm]
pnpm remove @nuxt/ui-pro
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn remove @nuxt/ui-pro
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm uninstall @nuxt/ui-pro
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun remove @nuxt/ui-pro
bun add @nuxt/ui tailwindcss
```

::

#nuxt sein
:::div

2. `@nuxt/ui-pro` mit `@nuxt/ui` in Ihrem `nuxt.config.ts`:

```diff [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
-   '@nuxt/ui-pro',
+   '@nuxt/ui'
  ]
})
```
:::

## Änderungen von v3

Nach dem Upgrade auf Nuxt UI v4, beachten Sie bitte die folgenden wichtigen Änderungen:

### Umbenannter ButtonGroup

`ButtonGroup` Komponente wurde umbenannt in [`FieldGroup`](/docs/components/field-group):

```diff
<template>
- <UButtonGroup>
+ <UFieldGroup>
    <UButton label="Button" />
    <UButton icon="i-lucide-chevron-down" />
+ </UFieldGroup>
- </UButtonGroup>
</template>
```

### Umbenanntes PageMarquee

Die `PageMarquee` Komponente wurde umbenannt in [`Marquee`](/docs/components/marquee):

```diff
<template>
- <UPageMarquee :items="items" />
+ <UMarquee :items="items" />
</template>
```

### Entfernte SeitenAkkordeon

Die `PageAccordion` Komponente wurde zugunsten von [`Accordion`](/docs/components/accordion):

```diff
<template>
- <UPageAccordion
+ <UAccordion
    :items="items"
+   :unmount-on-hide="false"
+   :ui="{ trigger: 'text-base', body: 'text-base text-muted' }"
  />
</template>
```

::note
Die Komponente `PageAccordion` war ein Wrapper, der `unmount-on-hide` auf `false` setzte und die `ui`-Prop.
::

### Umbenannte Modellmodifikatoren.

`modelModifiers` Form, die von [`Input`PH2222),[`InputNumber`](/docs/components/input-number) und [`Textarea`/docs/components/textarea)`nullable`verwendet wird:

1. Der Modifikator `nullify` wurde in `nullable` umbenannt (er konvertiert leere/leere Werte in `null`).
2. Ein neuer `optional` Modifikator wurde hinzugefügt (er wandelt leere/leere Werte in `undefined` um).

```diff
- <UInput v-model.nullify="value" />
+ <UInput v-model.nullable="value" />
```

```diff
- <UTextarea v-model="value" :model-modifiers="{ nullify: true }" />
+ <UTextarea v-model="value" :model-modifiers="{ nullable: true }" />
```

Verwenden Sie `nullable`, wenn Sie leere Werte als `null` und `optional`, wenn Sie `undefined` für fehlende Werte bevorzugen.

### Änderungen an Formularkomponenten

Die `Form`-Komponente wurde in v4 mit besserer Zustandsverwaltung und verschachtelten Formularhandling verbessert.

1. Schema**transformationen werden nur ** auf die **`@submit` data** angewendet und mutieren den Zustand des Formulars nicht mehr.
2. **geschachtelte Formulare müssen explizit ** aktiviert werden, indem die `nested` prop.
3. **Geschachtelte Formulare sollten nun eine `name`** prop (ähnlich wie `UFormField`) bereitstellen und werden automatisch ihren Status von ihrem übergeordneten Formular erben.

```diff
<template>
  <UForm :state="state" :schema="schema" @submit="onSubmit">
    <UFormField label="Customer" name="customer">
      <UInput v-model="state.customer" placeholder="Wonka Industries" />
    </UFormField>

    <div v-for="(item, index) in state.items" :key="index">
      <UForm
-       :state="item"
+       :name="`items.${index}`"
        :schema="itemSchema"
+       nested
      >
        <UFormField :label="!index ? 'Description' : undefined" name="description">
          <UInput v-model="item.description" />
        </UFormField>
        <UFormField :label="!index ? 'Price' : undefined" name="price">
          <UInput v-model="item.price" type="number" />
        </UFormField>
      </UForm>
    </div>
  </UForm>
</template>
```

### Entfernt veraltete Dienstprogramme

Einige **Nuxt-Inhaltsverwendungen **, die zuvor in Nuxt UI Pro verfügbar waren, wurden in v4 unter **removed** übertragen:

`findPageBreadcrumb`
`findPageHeadline`

Diese werden jetzt vollständig von Nuxt Content bereitgestellt. Stellen Sie sicher, dass Sie Ihre Importe und die Verwendung entsprechend aktualisieren.

```diff
- import { findPageHeadline } from '@nuxt/ui-pro/utils/content'
+ import { findPageHeadline } from '@nuxt/content/utils'

- import { findPageBreadcrumb } from '@nuxt/ui-pro/utils/content'
+ import { findPageBreadcrumb } from '@nuxt/content/utils'
```

### AI SDK-Migration (optional)

Dieser Abschnitt gilt nur, wenn Sie das AI SDK und die Chat-Komponenten verwenden (`ChatMessage`,`ChatMessages`,`ChatPrompt`,`ChatPromptSubmit`,`ChatPalette`).

1. Update `@ai-sdk/vue` und `ai` Abhängigkeiten in Ihrem `package.json` und fügen Sie [Comark]()(ersetzt `@nuxtjs/mdc` für das Rendern von AI-Antworten als Streaming-Markdown):

::framework-only
#nuxt sein
:::div
```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/nuxt": "latest"
  }
}
```

Fügen Sie `@comark/nuxt` zu Ihren Modulen hinzu:

```diff [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxt/ui',
+   '@comark/nuxt'
  ]
})
```
:::

#Ansehen
```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/vue": "latest"
  }
}
```
::

2. Die `useChat` composable API wurde geändert:`input` und `handleSubmit` wurden zugunsten von `sendMessage` entfernt, und `messages` ist jetzt eine Referenz, die Sie direkt festlegen:

```diff
<script setup lang="ts">
  import { useChat } from '@ai-sdk/vue'

- const { messages, input, handleSubmit, status, error, reload, setMessages } = useChat()
+ const { messages, status, error, sendMessage, regenerate, stop } = useChat()
+ const input = ref('')
+
+ function handleSubmit() {
+   sendMessage({ text: input.value })
+   input.value = ''
+ }
</script>
```

3. Nachrichten verwenden jetzt `parts` anstelle von `content`:

```diff
// When manually creating messages
- setMessages([{
+ messages.value = [{
  id: '1',
  role: 'user',
- content: 'Hello world'
+ parts: [{ type: 'text', text: 'Hello world' }]
- }])
+ }]

// In templates
<template>
- <UChatMessage :content="message.content" />
+ <UChatMessage :parts="message.parts" />
</template>
```

4. Einige Methoden wurden umbenannt:

```diff
// Regenerate the last message
- reload()
+ regenerate()
```

5. `<MDC>` mit `<Markdown>` für teilbasiertes Rendering. Die `Markdown` Komponente ist speziell für das Streaming von Markdown entwickelt worden, sie rendert inkrementell Token, wenn sie von den AI. Use AI SDK-Helfern und dem `isPartStreaming` Utility von `@nuxt/ui/utils/ai` kommen.

::note
Wenn Sie das `shiki` Plugin verwenden, fügen Sie das folgende CSS zu Ihrem Stylesheet hinzu, um den dunklen Modus zu unterstützen:

```css [main.css]
html.dark .shiki span {
  color: var(--shiki-dark) !important;
  background-color: var(--shiki-dark-bg) !important;
  font-style: var(--shiki-dark-font-style) !important;
  font-weight: var(--shiki-dark-font-weight) !important;
  text-decoration: var(--shiki-dark-text-decoration) !important;
}
```
::

::framework-only
#nuxt sein
```vue
<script setup lang="ts">
import { isReasoningUIPart, isTextUIPart } from 'ai'
import { isPartStreaming } from '@nuxt/ui/utils/ai'
import shiki from '@comark/nuxt/plugins/shiki'

const plugins = [shiki()]
</script>

<template>
  <UChatMessages :messages="messages" :status="status">
    <template #content="{ message }">
      <template v-for="(part, index) in message.parts" :key="`${message.id}-${part.type}-${index}`">
        <UChatReasoning
          v-if="isReasoningUIPart(part)"
          :text="part.text"
          :streaming="isPartStreaming(part)"
        >
          <Markdown
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="plugins"
            class="*:first:mt-0 *:last:mb-0"
          />
        </UChatReasoning>

        <template v-else-if="isTextUIPart(part)">
          <Markdown
            v-if="message.role === 'assistant'"
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="plugins"
            class="*:first:mt-0 *:last:mb-0"
          />
          <p v-else-if="message.role === 'user'" class="whitespace-pre-wrap">
            {{ part.text }}
          </p>
        </template>
      </template>
    </template>
  </UChatMessages>
</template>
```
