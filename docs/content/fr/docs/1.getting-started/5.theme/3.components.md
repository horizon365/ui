## Variants de tailwind

Les composants de l'interface utilisateur Nuxt sont stylisés à l'aide de l'API [Tailwind Variants](https://www.tailwind-variants.org/), qui fournit un moyen puissant de créer des variantes et de gérer les styles de composants.

@@005@@séries

Les composants peuvent avoir plusieurs `slots`, chacun représentant un élément ou une section HTML distincte au sein du composant.

Prenons l'exemple du composant [Card](/docs/components/card) qui a plusieurs emplacements:

::code-group

```ts [src/theme/card.ts]
export default {
  slots: {
    root: 'rounded-lg overflow-hidden',
    header: 'p-4 sm:px-6',
    title: 'text-highlighted font-semibold',
    description: 'mt-1 text-muted text-sm',
    body: 'p-4 sm:p-6',
    footer: 'p-4 sm:px-6'
  }
}
```

```vue [src/runtime/components/Card.vue]
<template>
  <Primitive :as="props.as" data-slot="root" :class="ui.root({ class: [props.ui?.root, props.class] })">
    <div data-slot="header" :class="ui.header({ class: props.ui?.header })">
      <slot name="header" />
    </div>

    <div data-slot="body" :class="ui.body({ class: props.ui?.body })">
      <slot />
    </div>

    <div data-slot="footer" :class="ui.footer({ class: props.ui?.footer })">
      <slot name="footer" />
    </div>
  </Primitive>
</template>
```

::

::note
Les composants réels portent également `v-if` gardes sur chaque fente et le thème définit `variant` styles sur le dessus des fentes.
::

Dans ce cas, le thème ne définit que l'emplacement `base` comme le composant [Container](/docs/components/container) par exemple:

::code-group

```ts [src/theme/container.ts]
export default {
  base: 'w-full max-w-(--ui-container) mx-auto px-4 sm:px-6 lg:px-8'
}
```

```vue [src/runtime/components/Container.vue]
<template>
  <Primitive :as="props.as" :class="ui({ class: [props.ui?.base, props.class] })">
    <slot />
  </Primitive>
</template>
```

::

::note
Les composants sans fentes ont toujours un [`ui` prop](). Il expose une seule clé `base` au lieu d'une clé par fente.[Link]() et [Icon](/docs/components/icon)sont les exceptions: ils n'ont pas de `ui` prop, alors utilisez le [`class` prop](#class-prop) pour remplacer leurs styles.
::

### Variétés

Les composants prennent en charge `variants`, qui ajustent dynamiquement les styles de différents `slots` en fonction des accessoires des composants.

Par exemple, le composant [Avatar](/docs/components/avatar) utilise une variante `size` pour contrôler son apparence:

```ts [src/theme/avatar.ts] {6-18}
export default {
  slots: {
    root: 'inline-flex items-center justify-center shrink-0 select-none overflow-hidden rounded-full align-middle bg-elevated',
    image: 'h-full w-full rounded-[inherit] object-cover'
  },
  variants: {
    size: {
      sm: {
        root: 'size-7 text-sm'
      },
      md: {
        root: 'size-8 text-base'
      },
      lg: {
        root: 'size-9 text-lg'
      }
    }
  },
  defaultVariants: {
    size: 'md'
  }
}
```

De cette façon, le prop `size` appliquera les styles correspondants à l'emplacement `root`:

### Variantes par défaut

La propriété `defaultVariants` définit la valeur par défaut pour chaque variante lorsqu 'aucun prop n'est passé.

Par exemple, le composant [Avatar](/docs/components/avatar) a sa taille par défaut définie à `md`:

```ts [src/theme/avatar.ts] {19-21}
export default {
  slots: {
    root: 'inline-flex items-center justify-center shrink-0 select-none overflow-hidden rounded-full align-middle bg-elevated',
    image: 'h-full w-full rounded-[inherit] object-cover'
  },
  variants: {
    size: {
      sm: {
        root: 'size-7 text-sm'
      },
      md: {
        root: 'size-8 text-base'
      },
      lg: {
        root: 'size-9 text-lg'
      }
    }
  },
  defaultVariants: {
    size: 'md'
  }
}
```

::framework-only
#numérique
:::tip{to="/docs/getting-started/installation/nuxt#themedefaultvariants"}
Vous pouvez utiliser l'option `theme.defaultVariants` dans votre `nuxt.config.ts` pour remplacer les `size` et `color` par défaut de chaque composant qui utilise `md` et `primary`.
:::

#vue
:::tip{to="/docs/getting-started/installation/vue#themedefaultvariants"}
Vous pouvez utiliser l'option `theme.defaultVariants` dans votre `vite.config.ts` pour remplacer les `size` et `color` par défaut de chaque composant qui utilise `md` et `primary`.
:::
::

### Variantes composées

Certains composants utilisent la propriété `compoundVariants` pour appliquer des classes lorsque plusieurs conditions de variantes sont remplies en même temps.

Par exemple, le composant [Button](/docs/components/button) utilise la propriété `compoundVariants` pour appliquer des classes pour une combinaison spécifique de `color` et `variant`:

```ts [src/theme/button.ts] {27-31}
import type { ModuleOptions } from '../module'

export default (options: Required<ModuleOptions>) => ({
  slots: {
    base: ['rounded-md font-medium inline-flex items-center disabled:cursor-not-allowed aria-disabled:cursor-not-allowed disabled:opacity-75 aria-disabled:opacity-75', options.theme.transitions && 'transition-colors']
  },
  variants: {
    color: {
      ...Object.fromEntries((options.theme.colors || []).map((color: string) => [color, ''])),
      neutral: ''
    },
    variant: {
      solid: '',
      outline: '',
      soft: '',
      subtle: '',
      ghost: '',
      link: ''
    }
  },
  compoundVariants: [
    ...(options.theme.colors || []).map((color: string) => ({
      color,
      variant: 'outline',
      class: `ring ring-inset ring-${color}/50 text-${color} hover:bg-${color}/10 active:bg-${color}/10 disabled:bg-transparent aria-disabled:bg-transparent dark:disabled:bg-transparent dark:aria-disabled:bg-transparent outline-${color}/25 focus-visible:outline-3 focus-visible:ring-${color}`
    })),
    {
      color: 'neutral',
      variant: 'outline',
      class: 'ring ring-inset ring-accented text-default bg-default hover:bg-elevated active:bg-elevated disabled:bg-default aria-disabled:bg-default outline-inverted/25 focus-visible:outline-3 focus-visible:ring-inverted'
    }
  ],
  defaultVariants: {
    color: 'primary',
    variant: 'solid'
  }
})
```

## Personnaliser le thème

Vous avez plusieurs façons de personnaliser l'apparence des composants de l'interface utilisateur Nuxt, vous pouvez le faire pour tous les composants à la fois ou par composant.

::note
Tailwind Variants utilise [`tailwind-merge`](https://github.com/dcastil/tailwind-merge) sous le capot pour fusionner des classes afin que vous n'ayez pas à vous soucier des classes conflictuelles.
::

::tip
Vous pouvez explorer le thème de chaque composant de deux manières:

- Consultez la section `Theme` dans la documentation de chaque composant.
- Parcourez le code source directement dans le dépôt GitHub à [`src/theme`](https://github.com/nuxt/ui/tree/v4/src/theme).
::

### config globale

::framework-only
#numérique
Vous pouvez remplacer le thème des composants globalement à l'intérieur de votre `app.config.ts` en utilisant exactement la même structure que l'objet thème.
#vue
Vous pouvez remplacer le thème des composants globalement à l'intérieur de votre `vite.config.ts` en utilisant exactement la même structure que l'objet thème.
::

Vous pouvez personnaliser le [`slots`](#slots),[`variants`](#variants),[`compoundVariants`](#compound-variants) et [`defaultVariants`](#default-variants) d'un composant pour modifier le thème par défaut d'un composant:

::framework-only
#numérique
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        base: 'font-bold'
      },
      variants: {
        size: {
          md: {
            leadingIcon: 'size-4'
          }
        }
      },
      compoundVariants: [{
        color: 'neutral',
        variant: 'outline',
        class: 'ring-default hover:bg-accented'
      }],
      defaultVariants: {
        color: 'neutral',
        variant: 'outline'
      }
    }
  }
})
```
:::

#vue
:::div
```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          slots: {
            base: 'font-bold'
          },
          variants: {
            size: {
              md: {
                leadingIcon: 'size-4'
              }
            }
          },
          compoundVariants: [{
            color: 'neutral',
            variant: 'outline',
            class: 'ring-default hover:bg-accented'
          }],
          defaultVariants: {
            color: 'neutral',
            variant: 'outline'
          }
        }
      }
    })
  ]
})
```
:::
::

::note
Dans cet exemple,`font-bold` remplace `font-medium` sur tous les boutons,`size-4` remplace la classe `size-5` sur l'icône principale lorsque `size="md"` et `ring-default hover:bg-accented` remplace `ring-accented hover:bg-elevated` lorsque `color="neutral"` et `variant="outline"`.
::

Par défaut, ces classes sont fusionnées sur les valeurs par défaut du composant. Vous pouvez également définir un emplacement pour une fonction pour les remplacer à la place. Il reçoit les classes par défaut de l'emplacement en tant qu 'argument, de sorte que vous pouvez réutiliser une partie d'entre elles. Les classes de `variants` et `compoundVariants` s'appliquent toujours en haut, exactement comme lorsque vous passez une chaîne.

::framework-only
#numérique
:::div
```ts [app/app.config.ts]
export default defineAppConfig({
  ui: {
    button: {
      slots: {
        label: () => 'text-base font-bold'
      }
    }
  }
})
```
:::

#vue
:::div
```ts [vite.config.ts]
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        button: {
          slots: {
            label: () => 'text-base font-bold'
          }
        }
      }
    })
  ]
})
```
:::
::

::framework-only
#numérique
:::warning
Définissez un emplacement pour une fonction à un seul endroit. Nuxt fusionne le `app.config.ts` de chaque [layer](https://nuxt.com/docs/getting-started/layers) avec `defuFn`, qui appelle votre fonction avec la valeur que la clé a déjà plus bas et ne conserve que le résultat. Nuxt UI lit ensuite une chaîne de caractères simple, de sorte que ses classes sont fusionnées sur les valeurs par défaut au lieu de les remplacer.
:::
::

::framework-only
#numérique
:::tip{to="/docs/getting-started/installation/nuxt#themeunstyled"}
Pour supprimer les classes par défaut de tous les composants en même temps, utilisez l'option `theme.unstyled` dans votre `nuxt.config.ts`.
:::

#vue
:::tip{to="/docs/getting-started/installation/vue#themeunstyled"}
Pour supprimer les classes par défaut de tous les composants en même temps, utilisez l'option `theme.unstyled` dans votre `vite.config.ts`.
:::
::

### Composant de thème

Le composant [Theme](/docs/components/theme) remplace les slots et les valeurs par défaut de prop pour tous ses descendants, sans affecter le reste de l'application.`ui` et `class`Les machines à sous acceptent la même forme de fonction pour remplacer leurs classes au lieu de fusionner. Elle est résolue au même point que le [`ui` prop ](#ui-prop), donc il se comporte de la même manière.

::component-example
---
nom: 'theme-exemple'
---
::

@@ph371@@@@ph372 @ prop

Vous pouvez également remplacer **slots** d'un composant en utilisant la prop.`ui`.

::component-code{slug="button"}
---
Étiquette: true
Ignorer:
  - ui.trailingIcon
  @@ph378@couleur
  - variant
  @@ph380@size
  @@ph381@icon
Props:
  Icône: i-lucide-chevron-right
  Taille: MD
  Couleur: Neutre
  Étiquette: Outline
  UI:
    trailingIcon: 'rotate-90 size-3'
Slots:
  Défaut:|

    bouton
---
::

::note
Dans cet exemple, l'emplacement `trailingIcon` est remplacé par `size-3` même si la variante de taille `md` lui appliquerait une classe `size-5`.
::

Une valeur de slot peut aussi être une fonction pour remplacer ses classes au lieu de les fusionner:

```vue
<template>
  <UButton :ui="{ label: () => 'text-base font-bold' }" label="Button" />
</template>
```

::note
Le `ui` prop est résolu après le `variants`, donc contrairement à la configuration globale, une fonction remplace ici les classes **resolved** du slot. Son argument contient ce que le `variants` et `compoundVariants` correspondent. Un `class` prop sur le même slot est toujours fusionné au-dessus des classes retournées.
::

@@@ph398@@@ph399 @@ prop

Utilisez la prop `class` pour remplacer les classes de l'emplacement `root` ou `base`. Ceci a la priorité sur la configuration globale et sur le `variants` résolu.

::component-code{slug="button"}
---
Props:
  classe: 'font-bold rounded-full'
Slots:
  Par défaut: Button
---
::

::note
Dans cet exemple, la classe `font-bold` remplacera la classe par défaut `font-medium` sur ce bouton.
::
