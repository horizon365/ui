## Structure du projet

Voici un aperçu des répertoires et fichiers clés de la structure du projet Nuxt UI:

### Documentation

La documentation se trouve dans le dossier `docs` en tant qu 'application Nuxt utilisant `@nuxt/content` pour générer des pages à partir de fichiers Markdown. Voir la documentation [Nuxt Content documentationhttps://content.nuxt.com/docs/getting-started) pour plus de détails sur son fonctionnement.

```bash
├── app/
│   ├── assets/
│   ├── components/
│   │   └── content/
│   │       └── examples   # Components used in documentation as examples
│   ├── composables/
│   └── ...
├── content/
│   ├── blog/
│   ├── docs/
│   │   ├── 1.getting-started
│   │   ├── 2.components   # Components documentation
│   │   ├── 3.composables
│   │   └── 4.typography
│   └── ...            # Landing pages (index.yml, showcase.yml...)
```

### Module

Le code du module se trouve dans le dossier `src`. Voici une ventilation de sa structure:

```bash
├── plugins/
├── runtime/
│   ├── components/        # Where all the components are located
│   │   ├── Accordion.vue
│   │   ├── Alert.vue
│   │   └── ...
│   ├── composables/
│   ├── locale/
│   ├── plugins/
│   ├── types/
│   ├── utils/
│   └── vue/
│       ├── components/
│       └── plugins/
├── theme/                 # This where the theme for each component is located
│   ├── accordion.ts       # Theme for Accordion component
│   ├── alert.ts
│   └── ...
├── utils/
└── module.ts
```

@@ph067@cli

Pour faciliter le développement, nous avons créé une CLI que vous pouvez utiliser pour générer des composants et des locales. Vous pouvez y accéder en utilisant la commande `pnpm cli make`.

### Composants

Vous pouvez créer de nouveaux composants en utilisant la commande suivante:

```bash
pnpm cli make component <name> [options]
```

options disponibles:

- `--primitive` Créer un composant primitif
- `--prose` Créer un composant en prose
- `--content` Créer un composant de contenu
- `--template` Générer uniquement un modèle spécifique (modèles disponibles: `playground`,`docs`,`test`,`theme`,`component`)

Exemple:

```bash
# Create a basic component
pnpm cli make component my-component

# Create a prose component
pnpm cli make component heading --prose

# Create a content component
pnpm cli make component block --content

# Generate only documentation template
pnpm cli make component my-component --template=docs
```

::note
Lors de la création d'un nouveau composant, la CLI génère automatiquement tous les fichiers nécessaires comme le composant lui-même, le thème, les tests et la documentation.
::

@@P099@@Régions

Vous pouvez créer de nouvelles locales en utilisant la commande suivante:

```bash
pnpm cli make locale --code <code>
```

Le nom et la direction locaux sont remplis à partir de [CLDR](https://cldr.unicode.org/) et le code est validé par rapport à celui-ci.

Une fois que vous avez traduit les messages, vous pouvez vérifier que vos paramètres régionaux restent cohérents avec les autres (touches de message, espaces réservés, nom et direction) en exécutant:

```bash
pnpm test locale --run
```

::note{to="/docs/getting-started/integrations/i18n/nuxt#supported-languages"}
En savoir plus sur **i18n** dans la documentation.
::

## Soumettre une demande de tirage (PR)

Avant de commencer, vérifiez s'il existe un problème existant décrivant le problème ou la demande de fonctionnalité sur laquelle vous travaillez. S'il y en a un, veuillez laisser un commentaire sur le problème pour nous faire savoir que vous y travaillez.

S'il n'y en a pas, ouvrez un nouveau numéro pour discuter du problème ou de la fonctionnalité.

### Développement local

Pour commencer le développement local, suivez ces étapes:

::steps{level="4"}

#### Clone le dépôt `nuxt/ui` sur votre machine locale

```bash
git clone -b v4 https://github.com/nuxt/ui.git
```

#### Activer [Corepack ](https://github.com/nodejs/corepack)

```bash
corepack enable
```

#### Installer des dépendances

```bash
pnpm install
```

#### Générer des stubs de type

```bash
pnpm run dev:prepare
```

#### Début du développement

- Pour travailler sur la **documentation** située dans le dossier `docs`, exécutez:

```bash
pnpm run docs
```

- Pour tester les composants Nuxt à l'aide du **playground**, exécutez:

```bash
pnpm run dev
```

- Pour tester les composants Vue en utilisant le **playground**, exécutez:

```bash
pnpm run dev:vue
```

::

::note{to="#cli"}
Si vous travaillez sur la mise en œuvre d'un nouveau composant, consultez la section **CLI** pour lancer le processus.
::

### Configuration de l'IDE

Nous vous recommandons d'utiliser VSCode à côté de l'extension [ESLint ](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint). Vous pouvez activer la correction automatique et le formatage lors de l'enregistrement de votre code.

```json [.vscode/settings.json]
{
  "editor.codeActionsOnSave": {
    "source.fixAll": "never",
    "source.fixAll.eslint": "explicit"
  },
  "prettier.enable": false
}
```

::warning
Étant donné que ESLint est déjà configuré pour formater le code, il n'est pas nécessaire de dupliquer la fonctionnalité avec **Prettier**. Si vous l'avez installé dans votre éditeur, nous vous recommandons de le désactiver pour éviter les conflits.
::

@175@Linting

Vous pouvez utiliser la commande `lint` pour vérifier les erreurs de linting:

```bash
pnpm run lint # check for linting errors
pnpm run lint:fix # fix linting errors
```

### Vérification de type

Nous utilisons TypeScript pour la vérification de type. Vous pouvez utiliser la commande `typecheck` pour rechercher les erreurs de type:

```bash
pnpm run typecheck
```

@@ph186@télécharger

Avant de soumettre un PR, assurez-vous d'exécuter les tests suivants:

```bash
pnpm run test
```

::tip
Si vous devez mettre à jour les snapshots, appuyez sur `u` après que les tests aient été exécutés.
::

### Commettre les conventions

Nous utilisons [Conventional Commits](https://www.conventionalcommits.org/) pour les messages de validation, ce qui permet de générer automatiquement un journal des changements en fonction des validations. Veuillez lire le [guide](https://www.conventionalcommits.org/en/v1.0.0/#summary) jusqu'à la fin si vous ne le connaissez pas déjà.

- Utilisez `fix` et `feat` pour les modifications de code qui affectent la fonctionnalité ou la logique
- Utilisez `docs` pour les modifications de documentation et `chore` pour les tâches de maintenance

### Faire une requête de tirage

- Suivez les [instructions](https://github.com/nuxt/ui/blob/v4/.github/PULL_REQUEST_TEMPLATE.md?plain=1) fournies lors de la création d'un RP

- Assurez-vous que le titre de votre RP adhère au [Conventional Commits](https://www.conventionalcommits.org/) puisqu 'il sera utilisé une fois le code fusionné.

- Les commits multiples sont corrects; pas besoin de rebaser ou de forcer le push. Nous utiliserons `Squash and Merge` lors de la fusion.

- Assurez-vous que `lint`,`typecheck` et `tests` travaillent avant de soumettre le RP. Évitez d'apporter des modifications sans rapport.

Nous allons l'examiner rapidement. S'il est assigné à un responsable, il l'examinera attentivement. Ignorez le texte rouge; c'est à des fins de suivi.
