## Utilisation

Nuxt UI enregistre automatiquement le module [`@nuxt/icon`](https://github.com/nuxt/icon) pour vous, aucune configuration supplémentaire n'est nécessaire.

Composant ### Icon

Vous pouvez utiliser le composant [Icon](/docs/components/icon) avec une prop `name` pour afficher une icône:

::component-code{slug="icon"}
---
props:
  name: 'i-lucide-lightbulb'
  class: 'size-5'
---
::

::note
Parcourez-les facilement sur <https://icones.js.org> ou recherchez directement à partir de votre assistant AI à l'aide de l'outil MCP [`search-icons`](xph022).
::

### Composants props

Some components also have a prop `icon` to display an icon, like the [Button](/docs/components/button) for example:

::component-code{slug="button"}
---
ignore:
  - color
  - variant
props:
  icon: i-lucide-sun
  variant: subtle
slots:
  default: Button
---
::

## Collections

### Iconify jeu de données

Il est fortement recommandé d'installer les données d'icônes localement avec:

::code-group{sync="pm"}

```bash [pnpm]
pnpm i @iconify-json/{collection_name}
```

```bash [yarn]
yarn add @iconify-json/{collection_name}
```

```bash [npm]
npm install @iconify-json/{collection_name}
```

::

Par exemple, pour utiliser l'icône `i-uil-github`, installez sa collection avec `@iconify-json/uil`. De cette façon, les icônes peuvent être servies localement ou à partir de vos fonctions sans serveur, ce qui est plus rapide et plus fiable à la fois côté SSR et côté client.

L'installation de la collection permet également à Nuxt UI d'intégrer les icônes qu 'il utilise dans le bundle client au moment de la construction, de sorte qu' elles sont disponibles sur le premier rendu au lieu d'être chargées à la demande à l'exécution. Cela se produit automatiquement pour les propres icônes de Nuxt UI, à partir de la collection `lucide` par défaut. Pour regrouper d'autres icônes, telles que celles que vous remplacez ou utilisez ailleurs dans votre application, Ajoutez-les à l'option [`clientBundle.icons`](https://github.com/nuxt/icon?tab=readme-ov-file#client-bundle) de `@nuxt/icon` dans votre `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      icons: ['lucide:heart', 'simple-icons:github']
    }
  }
})
```

Vous pouvez également activer `clientBundle.scan` pour regrouper toutes les icônes utilisées dans votre application en analysant votre source, de sorte que vous n'avez pas à les lister une par une:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: true
    }
  }
})
```

La numérisation lit uniquement les fichiers `.vue`, `.jsx`, `.tsx`, `.md`, `.mdc`, `.mdx`, `.yml` et `.yaml`, et ne correspond qu 'aux noms d'icônes écrits sous forme de chaînes littérales. tout comme les noms construits dynamiquement comme `i-lucide-${name}`. Définissez `globInclude` pour analyser ces fichiers également. Il remplace la liste par défaut, alors gardez les extensions dont vous avez toujours besoin:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: {
        globInclude: ['**/*.{vue,jsx,tsx,md,mdc,mdx,yml,yaml,ts,js}']
      }
    }
  }
})
```

Les noms dynamiques peuvent toujours être regroupés lorsque vous connaissez l'ensemble au moment de la compilation, en les listant dans `clientBundle.icons`. Les noms qui n'existent qu'à l'exécution, comme les icônes provenant d'une API, ne peuvent pas être regroupés du tout. Ils sont chargés à la demande à partir de la route `/api/_nuxt_icon` lorsque votre application est rendue par le serveur, avec l'API Iconify en tant que solution de secours, et à partir de l'API Iconify directement lorsque vous utilisez `nuxt generate` ou `ssr: false`.

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#iconify-dataset" target="_blank"}
Pour en savoir plus, consultez la documentation du `@nuxt/icon`.
::

### Collections locales personnalisées

Vous pouvez utiliser les fichiers SVG locaux pour créer une collection Iconify personnalisée.

Par exemple, placez les fichiers SVG de vos icônes dans un dossier de votre choix, par exemple, `./app/assets/icons`:

```bash
assets/icons
├── add.svg
└── remove.svg
```

Dans votre `nuxt.config.ts`, ajoutez un élément dans votre `icon.customCollections`:

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    customCollections: [{
      prefix: 'custom',
      dir: './app/assets/icons'
    }]
  }
})
```

Vous pouvez utiliser des icônes comme ceci:

```vue
<template>
  <UIcon name="i-custom-add" />
</template>
```

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#custom-local-collections" target="_blank"}
Pour en savoir plus, consultez la documentation sur le `@nuxt/icon`.
::

## Thème

Vous pouvez modifier les icônes par défaut utilisées par les composants de votre `app.config.ts`:

:icons-theme-select

:icons-theme

::note
Les icônes que vous remplacez dans `app.config.ts` sont chargées à la demande au moment de l'exécution plutôt que d'être intégrées dans le paquet client. Pour les regrouper également, ajoutez-les sous forme `{collection}:{name}` (par exemple `lucide:rocket`) au [`clientBundle.icons`](https://github.com/nuxt/icon?tab=readme-ov-file#client-bundle) de ) dans votre `nuxt.config.ts`.
::
