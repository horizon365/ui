@@ph002@utilisation

Nuxt UI enregistre automatiquement le module [`@nuxt/icon`](https://github.com/nuxt/icon) pour vous, aucune configuration supplémentaire n'est donc nécessaire.

### Icon composant

Vous pouvez utiliser le composant [Icon](/docs/components/icon) avec un prop `name` pour afficher une icône:

::component-code{slug="icon"}
---
Props:
  Étiquette: i-lucide-lightbulb
  Catégorie:'Size-5'
---
::

::note
Vous pouvez utiliser n'importe quel nom de la collection <https://iconify.design>. Parcourez-les facilement sur <https://icones.js.org> ou recherchez directement à partir de votre assistant AI à l'aide de l'outil MCP [`search-icons`](/docs/getting-started/ai/mcp#available-tools).
::

### Composants props

Certains composants ont également un `icon` prop pour afficher une icône, comme le [Button](/docs/components/button) par exemple:

::component-code{slug="button"}
---
Ignorer:
  @@27@couleur
  @@28@variété
Props:
  Étiquette: i-lucide-sun
  Variante: subtile
Slots:
  Par défaut: Button
---
::

## Collections

### Iconify jeu de données

Il est fortement recommandé d'installer les données d'icônes localement avec:

::code-group{sync="pm"}

```bash [pnpm]
pnpm i @iconify-json/{collection_name}
```

```bash [yarn]
yarn add @iconify-json/{collection_name}
```

```bash [npm]
npm install @iconify-json/{collection_name}
```

::

Par exemple, pour utiliser l'icône `i-uil-github`, installez sa collection avec `@iconify-json/uil`. De cette façon, les icônes peuvent être servies localement ou à partir de vos fonctions sans serveur, ce qui est plus rapide et plus fiable à la fois sur SSR et côté client.

L'installation de la collection permet également à Nuxt UI d'intégrer les icônes qu 'il utilise dans le bundle client au moment de la construction, de sorte qu' elles sont disponibles lors du premier rendu au lieu d'être chargées à la demande lors de l'exécution. Cela se produit automatiquement pour les icônes propres à Nuxt UI, de la collection `lucide` par défaut. Pour regrouper d'autres icônes, telles que celles que vous remplacez ou utilisez ailleurs dans votre application, ajoutez-les à `@nuxt/icon`'s [`clientBundle.icons`](https://github.com/nuxt/icon?tab=readme-ov-file#client-bundle) dans votre `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      icons: ['lucide:heart', 'simple-icons:github']
    }
  }
})
```

Vous pouvez également activer `clientBundle.scan` pour regrouper toutes les icônes utilisées dans votre application en scannant votre source, de sorte que vous n'avez pas à les lister une par une:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: true
    }
  }
})
```

La numérisation ne lit que les fichiers `.vue`,`.jsx`,`.tsx`,`.md`,`.mdc`,`.mdx`,`.yml` et `.yaml`, et ne correspond qu 'aux noms d'icônes écrits sous forme de chaînes littérales. tout comme les noms construits dynamiquement comme `i-lucide-${name}`. Définissez `globInclude` pour analyser ces fichiers aussi bien. Il remplace la liste par défaut, donc gardez les extensions dont vous avez toujours besoin:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: {
        globInclude: ['**/*.{vue,jsx,tsx,md,mdc,mdx,yml,yaml,ts,js}']
      }
    }
  }
})
```

Les noms dynamiques peuvent toujours être regroupés lorsque vous connaissez l'ensemble au moment de la construction, en les répertoriant dans `clientBundle.icons`. Les noms qui n'existent qu 'au moment de l'exécution, comme les icônes provenant d'une API, ne peuvent pas être regroupés du tout. Ils sont chargés à la demande à partir de la route `/api/_nuxt_icon` lorsque votre application est rendue par le serveur, avec l'API Iconify comme solution de secours, et directement à partir de l'API Iconify lorsque vous utilisez `nuxt generate` ou `ssr: false`.

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#iconify-dataset" target="_blank"}
En savoir plus à ce sujet dans la documentation `@nuxt/icon`.
::

### Collections locales sur mesure

Vous pouvez utiliser des fichiers SVG locaux pour créer une collection Iconify personnalisée.

Par exemple, placez les fichiers SVG de vos icônes dans un dossier de votre choix, par exemple,`./app/assets/icons`:

```bash
assets/icons
├── add.svg
└── remove.svg
```

Dans votre `nuxt.config.ts`, ajoutez un élément dans `icon.customCollections`:

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    customCollections: [{
      prefix: 'custom',
      dir: './app/assets/icons'
    }]
  }
})
```

Vous pouvez utiliser des icônes comme ceci:

```vue
<template>
  <UIcon name="i-custom-add" />
</template>
```

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#custom-local-collections" target="_blank"}
Pour en savoir plus, consultez la documentation `@nuxt/icon`.
::

: icons-thème-sélectionner

Icônes Thème

::note
Les icônes que vous remplacez dans `app.config.ts` sont chargées à la demande au moment de l'exécution plutôt que d'être intégrées dans le bundle client. Pour les regrouper également, ajoutez-les sous forme `{collection}:{name}`(par exemple `lucide:rocket`) au [`clientBundle.icons`https://github.com/nuxt/icon?tab=readme-ov-file#client-bundledans votre `nuxt.config.ts`.
::
