## Utilisation

L'interface utilisateur Nuxt embarque un composant `Icon` soutenu par [`@iconify/vue`](https://iconify.design/docs/icon-components/vue/), donc aucune configuration supplémentaire n'est requise.

Composant ### Icon

Vous pouvez utiliser le composant [Icon](/docs/components/icon) avec une prop `name` pour afficher une icône:

::component-code{slug="icon"}
---
props:
  name: 'i-lucide-lightbulb'
  class: 'size-5'
---
::

::note
Parcourez-les facilement sur <https://icones.js.org> ou recherchez directement à partir de votre assistant AI à l'aide de l'outil MCP [`search-icons`xph022/docs/getting-started/ai/mcp#available-tools).
::

::warning
Lorsque vous utilisez des collections avec un tiret (`-`), vous devez séparer le nom de l'icône du nom de la collection avec un deux-points (`:`) car `@iconify/vue` ne gère pas cette casse comme `@nuxt/icon`.

En savoir plus sur la convention de nommage [Iconify ](https://iconify.design/docs/icon-components/vue/#icon).
::

### Composants props

Certains composants disposent également d'un prop `icon` pour afficher une icône, comme le [Button](/docs/components/button) par exemple:

::component-code{slug="button"}
---
ignore:
  - color
  - variant
props:
  icon: i-lucide-sun
  variant: subtle
slots:
  default: Button
---
::

## Collections

### Iconify jeu de données

Il est fortement recommandé d'installer les données d'icônes localement avec:

::code-group{sync="pm"}

```bash [pnpm]
pnpm i @iconify-json/{collection_name}
```

```bash [yarn]
yarn add @iconify-json/{collection_name}
```

```bash [npm]
npm install @iconify-json/{collection_name}
```

::

Par exemple, pour utiliser l'icône `i-lucide-lightbulb`, installez sa collection avec `@iconify-json/lucide`.

L'installation de la collection permet à Nuxt UI d'intégrer les icônes qu 'elle utilise dans votre build, de sorte qu' elles soient immédiatement affichées pendant la SSR et fonctionnent entièrement hors ligne au lieu d'être récupérées à partir de l'API Iconify lors de l'exécution.

Pour regrouper d'autres icônes, telles que celles que vous remplacez ou utilisez ailleurs dans votre application, ajoutez-les à l'option `icon.clientBundle.icons` dans votre `vite.config.ts`:

```ts [vite.config.ts]
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    ui({
      icon: {
        clientBundle: {
          icons: ['lucide:heart', 'simple-icons:github']
        }
      }
    })
  ]
})
```

::note
Vous pouvez utiliser soit la forme `i-{collection}-{name}` ou `{collection}:{name}`, par exemple `i-lucide-heart` ou `lucide:heart`, et `i-material-symbols-menu` ou `material-symbols:menu`.
::

Pour regrouper les icônes que vous utilisez sans les répertorier une par une, activez `scan` à la place. Il analyse votre source pour les utilisations d'icônes de vos collections installées et les regroupe, de la même manière que `clientBundle.scan` de `@nuxt/icon` fonctionne:

```ts [vite.config.ts]
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    ui({
      icon: {
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

La numérisation lit uniquement les fichiers `.vue`, `.jsx`, `.tsx`, `.md`, `.mdc`, `.mdx`, `.yml` et `.yaml`, et ne correspond qu 'aux noms d'icônes écrits sous forme de chaînes littérales. tout comme les noms construits dynamiquement comme `i-lucide-${name}`. Définissez `globInclude` pour analyser ces fichiers aussi bien. Il remplace la liste par défaut, alors gardez les extensions dont vous avez toujours besoin:

```ts [vite.config.ts]
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    ui({
      icon: {
        clientBundle: {
          scan: {
            globInclude: ['**/*.{vue,jsx,tsx,md,mdc,mdx,yml,yaml,ts,js}']
          }
        }
      }
    })
  ]
})
```

Les noms dynamiques peuvent toujours être regroupés lorsque vous connaissez l'ensemble au moment de la construction, en les répertoriant dans `clientBundle.icons`. Les noms qui n'existent qu'à l'exécution, comme les icônes provenant d'une API, ne peuvent pas être regroupés du tout et sont chargés à partir de l'API Iconify à la demande.

Les icônes dont la collection n'est pas installée se chargent toujours à partir de l'API Iconify au moment de l'exécution, installez donc chaque collection que vous utilisez avec `@iconify-json/{collection_name}`.
