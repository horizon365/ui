Nuxt UI v4 marque une étape majeure: **Nuxt UI et Nuxt UI Pro sont désormais unifiés en une seule bibliothèque entièrement open-source et gratuite **. Vous avez désormais accès à plus de 125 composants prêts pour la production, tous disponibles dans le package `@nuxt/ui`.

::note
Nuxt UI v4 nécessite **Nuxt 4.1 ou ultérieure** en raison de certaines dépendances. Assurez-vous de mettre à niveau avant de migrer vers Nuxt UI v4.
::

Ce guide fournit des instructions étape par étape pour migrer votre application de la v3 à la v4.

## Migrer votre projet

### de Nuxt UI Pro

1. Remplacer `@nuxt/ui-pro` par `@nuxt/ui` dans votre `package.json`:

::code-group{sync="pm"}

```bash [pnpm]
pnpm remove @nuxt/ui-pro
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn remove @nuxt/ui-pro
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm uninstall @nuxt/ui-pro
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun remove @nuxt/ui-pro
bun add @nuxt/ui tailwindcss
```

## Changements depuis la v3

Après la mise à niveau vers Nuxt UI v4, veuillez noter les changements importants suivants:

### Renommée ButtonGroup

Le composant `ButtonGroup` a été renommé en [`FieldGroup`](/docs/components/field-group):

```diff
<template>
- <UButtonGroup>
+ <UFieldGroup>
    <UButton label="Button" />
    <UButton icon="i-lucide-chevron-down" />
+ </UFieldGroup>
- </UButtonGroup>
</template>
```

### Renommée PageMarquee

Le composant `PageMarquee` a été renommé en [`Marquee`](/docs/components/marquee):

```diff
<template>
- <UPageMarquee :items="items" />
+ <UMarquee :items="items" />
</template>
```

### PageSupprimé Accordéon

Le composant `PageAccordion` a été supprimé en faveur du [`Accordion`](/docs/components/accordion):

```diff
<template>
- <UPageAccordion
+ <UAccordion
    :items="items"
+   :unmount-on-hide="false"
+   :ui="{ trigger: 'text-base', body: 'text-base text-muted' }"
  />
</template>
```

::note
Le composant `PageAccordion` était un wrapper qui définissait `unmount-on-hide` à `false` et personnalisait le `ui` prop.
::

### Modificateurs de modèle renommés

La forme `modelModifiers` utilisée par [`Input`/docs/components/input),[](/docs/components/input-number) et [](/docs/components/textarea) a changé dans v4:

1. Le modificateur `nullify` a été renommé en `nullable`(il convertit les valeurs vides/vierges en `null`).
2. Un nouveau modificateur `optional` a été ajouté (il convertit les valeurs vides/vides en `undefined`).

```diff
- <UInput v-model.nullify="value" />
+ <UInput v-model.nullable="value" />
```

```diff
- <UTextarea v-model="value" :model-modifiers="{ nullify: true }" />
+ <UTextarea v-model="value" :model-modifiers="{ nullable: true }" />
```

Utilisez `nullable` lorsque vous voulez des valeurs vides comme `null`, et `optional` lorsque vous préférez `undefined` pour les valeurs absentes.

### Modifications apportées au composant de formulaire

Le composant `Form` a été amélioré dans la v4 avec une meilleure gestion des états et une gestion des formulaires imbriqués. Voici les principaux changements dont vous devez être conscient:

1. Schema **transformations ne seront appliquées qu 'aux **`@submit` data** et ne modifieront plus l'état de la forme.
2. **Les formulaires imbriqués doivent être activés explicitement ** en utilisant la prop.`nested`. Cela rend le comportement du composant plus explicite et empêche la création accidentelle de formulaires imbriqués.
3. **Les formulaires imbriqués devraient maintenant fournir un prop `name`**(similaire à `UFormField`) et hériteront automatiquement de leur état de leur formulaire parent.

```diff
<template>
  <UForm :state="state" :schema="schema" @submit="onSubmit">
    <UFormField label="Customer" name="customer">
      <UInput v-model="state.customer" placeholder="Wonka Industries" />
    </UFormField>

    <div v-for="(item, index) in state.items" :key="index">
      <UForm
-       :state="item"
+       :name="`items.${index}`"
        :schema="itemSchema"
+       nested
      >
        <UFormField :label="!index ? 'Description' : undefined" name="description">
          <UInput v-model="item.description" />
        </UFormField>
        <UFormField :label="!index ? 'Price' : undefined" name="price">
          <UInput v-model="item.price" type="number" />
        </UFormField>
      </UForm>
    </div>
  </UForm>
</template>
```

### Suppression des utilitaires dépréciés

Certaines utilités **Nuxt Content ** qui étaient auparavant disponibles dans Nuxt UI Pro ont été **supprimées ** dans la v4:

@@
@@

Ceux-ci sont désormais entièrement fournis par Nuxt Content. Assurez-vous de mettre à jour vos importations et votre utilisation en conséquence.

```diff
- import { findPageHeadline } from '@nuxt/ui-pro/utils/content'
+ import { findPageHeadline } from '@nuxt/content/utils'

- import { findPageBreadcrumb } from '@nuxt/ui-pro/utils/content'
+ import { findPageBreadcrumb } from '@nuxt/content/utils'
```

### AI SDK migration (optionnel)

Cette section s'applique uniquement si vous utilisez le kit de développement intelligent (SDK) et les composants de chat (`ChatMessage`,`ChatMessages`,`ChatPrompt`,`ChatPromptSubmit`,`ChatPalette`). Si vous n'utilisez pas les fonctionnalités d'IA, vous pouvez ignorer cette section.

1. Update `@ai-sdk/vue` et `ai` dans vos `package.json` et ajoutez [Comark](https://comark.dev)(remplace `@nuxtjs/mdc` pour le rendu des réponses AI en tant que Markdown en streaming):

::framework-only
#numérique
:::div
```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/nuxt": "latest"
  }
}
```

Ajoutez `@comark/nuxt` à vos modules:

```diff [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    '@nuxt/ui',
+   '@comark/nuxt'
  ]
})
```
:::

#vue
```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/vue": "latest"
  }
}
```
::

2. L'API composable `useChat` a changé:`input` et `handleSubmit` ont été supprimés en faveur de `sendMessage`, et `messages` est maintenant une référence que vous définissez directement:

```diff
<script setup lang="ts">
  import { useChat } from '@ai-sdk/vue'

- const { messages, input, handleSubmit, status, error, reload, setMessages } = useChat()
+ const { messages, status, error, sendMessage, regenerate, stop } = useChat()
+ const input = ref('')
+
+ function handleSubmit() {
+   sendMessage({ text: input.value })
+   input.value = ''
+ }
</script>
```

3. Messages utilisent maintenant `parts` au lieu de `content`:

```diff
// When manually creating messages
- setMessages([{
+ messages.value = [{
  id: '1',
  role: 'user',
- content: 'Hello world'
+ parts: [{ type: 'text', text: 'Hello world' }]
- }])
+ }]

// In templates
<template>
- <UChatMessage :content="message.content" />
+ <UChatMessage :parts="message.parts" />
</template>
```

4. Quelques méthodes ont été renommées:

```diff
// Regenerate the last message
- reload()
+ regenerate()
```

5. Remplacer `<MDC>` par `<Markdown>` pour le rendu basé sur les pièces. Le composant `Markdown` est spécialement conçu pour le streaming Markdown, il rend incrémentiellement les jetons à mesure qu 'ils arrivent de l'IA. Utilisez les assistants du SDK AI et l'utilitaire `isPartStreaming` de `@nuxt/ui/utils/ai`.

::note
Lorsque vous utilisez le plugin `shiki`, ajoutez le CSS suivant à votre feuille de style pour la prise en charge du mode sombre:

```css [main.css]
html.dark .shiki span {
  color: var(--shiki-dark) !important;
  background-color: var(--shiki-dark-bg) !important;
  font-style: var(--shiki-dark-font-style) !important;
  font-weight: var(--shiki-dark-font-weight) !important;
  text-decoration: var(--shiki-dark-text-decoration) !important;
}
```
::

::framework-only
#numérique
```vue
<script setup lang="ts">
import { isReasoningUIPart, isTextUIPart } from 'ai'
import { isPartStreaming } from '@nuxt/ui/utils/ai'
import shiki from '@comark/nuxt/plugins/shiki'

const plugins = [shiki()]
</script>

<template>
  <UChatMessages :messages="messages" :status="status">
    <template #content="{ message }">
      <template v-for="(part, index) in message.parts" :key="`${message.id}-${part.type}-${index}`">
        <UChatReasoning
          v-if="isReasoningUIPart(part)"
          :text="part.text"
          :streaming="isPartStreaming(part)"
        >
          <Markdown
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="plugins"
            class="*:first:mt-0 *:last:mb-0"
          />
        </UChatReasoning>

        <template v-else-if="isTextUIPart(part)">
          <Markdown
            v-if="message.role === 'assistant'"
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="plugins"
            class="*:first:mt-0 *:last:mb-0"
          />
          <p v-else-if="message.role === 'user'" class="whitespace-pre-wrap">
            {{ part.text }}
          </p>
        </template>
      </template>
    </template>
  </UChatMessages>
</template>
```
