### Ajouter à un projet Vue

::steps{level="4"}

#### Installer le paquet Nuxt UI

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

#### Ajoutez le plugin Nuxt UI Vite dans votre`vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI enregistre`unplugin-auto-import`et`unplugin-vue-components`, ce qui générera les fichiers de déclaration de type`auto-imports.d.ts`et`components.d.ts`. Vous voudrez probablement les gitignore et les ajouter à votre`tsconfig`.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
Ces fichiers de déclaration ne sont écrits que lorsque Vite s'exécute . Le script par défaut`create-vue`exécute`vue-tsc`en parallèle avec`vite build`(`run-p type-check "build-only {@}"`) , donc lors d'une vérification de type propre peut commencer avant que les fichiers n'existent et échouer avec des erreurs comme`Cannot find name 'useToast'`. Exécutez la vérification de type après la construction pour que les déclarations soient générées en premier .

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
En interne , l'interface utilisateur Nuxt s'appuie sur des alias personnalisés pour résoudre les types de thèmes . Si vous utilisez TypeScript , ajoutez ces alias à vos fichiers`tsconfig`pour activer la complétion automatique dans votre`vite.config.ts`.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```

#### Utilisez le plugin Nuxt UI Vue

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

```blade [resources/views/app.blade.php (Laravel Inertia)]{10}
    </div>
  </body>
```

```edge [resources/views/inertia_layout.edge (AdonisJS Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">
```

## Options

Vous pouvez personnaliser l'interface utilisateur Nuxt en fournissant des options dans votre`vite.config.ts`.

@@

Utilisez l'option `prefix` pour modifier le préfixe des composants.

- Default:`U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

@@

Utilisez l'option `ui` pour fournir la configuration de l'interface utilisateur Nuxt. C'est l'équivalent Vue de la clé `ui` dans le `app.config.ts` de Nuxt.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

@@

Utilisez l'option `dts` pour activer ou désactiver la génération de fichiers de déclaration pour les composants et les composables importés automatiquement.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

@@

Utilisez l'option `icon` pour définir les props par défaut pour le composant [Icon](/docs/components/icon)(`size`,`mode`, et `mode`)`customize`) et pour configurer le regroupement d'icônes au moment de la construction via `clientBundle`. Le regroupement des icônes de Nuxt UI est activé par défaut lors de l'installation de leur collection. Set`clientBundle: false` pour se désinscrire.

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
En savoir plus sur les collections d'icônes et le regroupement de clients dans la documentation **Icons**.
::

@@

Utilisez l'option `colorMode` pour activer ou désactiver l'intégration du mode couleur de `@vueuse/core`.

- Par défaut:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

@@

Utilisez l'option `theme.colors` pour définir les alias de couleurs dynamiques utilisés pour générer le thème des composants.

- Default:`['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Chaque alias génère un ensemble complet de teintes et de variantes `--ui-color-*` dans les thèmes de composants qui ont des variantes de couleur, que votre application l'utilise ou non. Coupez la liste aux alias que vous utilisez réellement et conservez `error` si vous utilisez des formulaires, car les styles de validation en dépendent.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
En savoir plus sur la personnalisation des couleurs et la thématisation dans la section Thème.
::

@@

Utilisez l'option `theme.transitions` pour activer ou désactiver les transitions sur les composants.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
Cette option ajoute la classe `transition-colors` sur les composants avec des états de survol ou actifs.
::

### `theme.unstyled`: badge{label="4.9+" class="align-text-top"}

Utilisez l'option `theme.unstyled` pour supprimer toutes les classes de thème par défaut des composants, en ne conservant que leur structure et les classes que vous fournissez via `class`,`ui` ou `app.config.ui`.

- Par défaut:`false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Cela supprime aussi les classes **structural**(positionnement, transitions, flex/grille), pas seulement les classes cosmétiques. Les composants lourds en termes de mise en page comme `Modal`,`Drawer` ou `Calendar` auront besoin de vous pour réapprovisionner leur mise en page, similaire au mode non stylé de PrimeVue.
::

@@

Utilisez l'option `theme.defaultVariants` pour remplacer les variantes par défaut `color` et `size` pour les composants.

Seuls les paramètres par défaut qui sont exactement `primary` ou `md` sont remplacés, donc Avatar garde `color: 'neutral'` et Separator garde `size: 'xs'`.

- Default:`{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix`: badge

Utilisez l'option `theme.prefix` pour configurer le même préfixe que celui que vous avez défini sur votre importation CSS Tailwind. Cela garantit que les composants de l'interface utilisateur Nuxt utilisent les classes utilitaires et les variables CSS préfixées correctes.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Cela préfixe automatiquement toutes les classes d'utilitaires Tailwind et les variables CSS dans les thèmes de composants Nuxt UI:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
En savoir plus sur l'utilisation d'un préfixe dans la documentation CSS de Tailwind.
::

@@

Utilisez l'option `prose` pour activer les composants de l'interface utilisateur Nuxt [`Prose`]()et leur thème.

- Default:`false`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prose: true
    })
  ]
})
```

@@

Utilisez l'option `autoImport` pour désactiver les importations automatiques composables ou pour personnaliser les options [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import).

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      autoImport: false
    })
  ]
})
```

::note
Lorsqu 'il est désactivé, vous pouvez toujours importer des composables explicitement à partir de `@nuxt/ui/composables`.
::

@@ph701 @

Utilisez l'option `components` pour désactiver l'importation automatique de composants ou pour personnaliser les options [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components).

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      components: false
    })
  ]
})
```

::note
When disabled, you can still import components explicitly, e.g.`import Button from '@nuxt/ui/components/Button.vue'` or `import ProseCode from '@nuxt/ui/components/prose/Code.vue'`.
::

### `router`: badge{label="4.3+" class="align-text-top"}

Utilisez l'option `router` pour configurer l'intégration de routage. Ceci est utile pour les applications qui n'utilisent pas `vue-router`, telles que les applications Electron, les MPA ou les frameworks tels que [https://inertiajs.com/) ou [Hybridly](https://hybridly.dev/).

- Default:`true`{lang="ts-type"}

| Valeur| Description|
| ----- | ----------- |
| @@ph744@| Utilise`vue-router`pour la navigation avec le composant`RouterLink`.|

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```

### `scanPackages`: badge{label="4.3+" class="align-text-top"}

Use the`scanPackages`option to specify additional npm packages that should be scanned for components using Nuxt UI . This is useful when you have a shared component library that uses Nuxt UI components internally .

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
Par défaut , seul`@nuxt/ui`est analysé . Utilisez cette option lorsque vos paquets externes contiennent des composants Vue qui utilisent l'interface utilisateur Nuxt .
::

### `root`: badge{label="4.9+" class="align-text-top"}

Utilisez l'option`root`pour remplacer le répertoire où Nuxt UI génère son répertoire`.nuxt-ui`(contenant les modèles de thème) . Par défaut , il utilise`root`de Vite , mais dans des configurations comme[`electron-vite`](https://electron-vite.org/)du moteur de rendu`root`pointe vers un sous-répertoire (par exemple`src/renderer`) , de sorte que les modèles atterrissent dans`src/renderer/node_modules/.nuxt-ui`où Tailwind ne les analyse pas , ce qui fait que les classes de thèmes comme`bg-default`,`ring-default`et`divide-default`sont manquantes .

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Pointez`root`à la racine de votre projet afin que le répertoire`.nuxt-ui`généré se retrouve dans un`node_modules`que Tailwind analyse .
::

### `experimental.componentDetection`: badge{label="4.11+" class="align-text-top"}

Utilisez l'option`experimental.componentDetection`pour activer la détection automatique des composants pour le tremblement des arbres . Cette fonctionnalité analyse votre code source pour détecter les composants réellement utilisés et génère uniquement le CSS nécessaire pour ces composants .(y compris leurs dépendances) . Sans cela , le plugin Vite génère le thème CSS pour chaque composant . Detection couvre la racine de Vite , les paquets listés dans[`scanPackages`](#scanpackages)et tout`dirs`de l'option[`components`](#components)située en dehors de la racine .

- Default :`false`{lang="ts-type"}
- Type :`boolean | string[]`{lang="ts-type"}

**Activer la détection automatique :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**Inclure des composants supplémentaires pour une utilisation dynamique :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Lorsque vous fournissez un tableau de noms de composants , la détection automatique est activée et ces composants (ainsi que leurs dépendances) sont garantis d'être inclus . Ceci est utile pour les composants dynamiques comme`<component :is="..." />`qui ne peuvent pas être analysés statiquement .
::

::warning
Les composants nouvellement utilisés sont récupérés lors du prochain démarrage du serveur de développement . Si vous ajoutez un composant et que ses styles sont manquants , redémarrez le serveur de développement .
::

## Libération continue

Nuxt UI utilise le[pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)pour des versions de prévisualisation continues , offrant aux développeurs un accès instantané aux dernières fonctionnalités et corrections de bogues sans attendre les versions officielles .

Des versions d'aperçu automatiques sont créées pour tous les commits et les PR de la branche`v4`. Utilisez-les en remplaçant la version de votre paquet par le hachage de commit ou le numéro de PR.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
@@@ph918@pkg.pr.new**commentera automatiquement les RP avec l'URL d'installation , ce qui facilite le test des modifications .
::
