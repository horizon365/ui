## Réseau

### Ajouter à un projet Nuxt

::steps{level="4"}

#### Installer le package Nuxt UI

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Ajouter le module Nuxt UI dans votre `nuxt.config.ts`{lang="ts-type"}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui']
})
```

::note
Il n'est pas nécessaire d'ajouter `@nuxt/icon`, `@nuxt/fonts` ou `@nuxtjs/color-mode` à votre tableau `modules` car Nuxt UI les enregistre automatiquement. Vous pouvez toujours configurer ces modules dans votre `nuxt.config.ts` à l'aide des touches `icon`, `fonts` et `colorMode`.
::

#### Import Tailwind CSS et Nuxt UI dans votre CSS

::code-group

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
```

```ts [nuxt.config.ts] {3}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css']
})
```

::

::tip{to="https://nuxt.com/docs/getting-started/layers" target="_blank"}
Lorsque vous utilisez [Nuxt Layers](https://nuxt.com/docs/getting-started/layers), le module génère automatiquement des directives [xph044](https://tailwindcss.com/docs/functions-and-directives#source-directive) pour chaque répertoire de couche, ce qui garantit que Tailwind CSS analyse tous vos fichiers sources de couche pour les classes d'utilitaires.
::

::callout{icon="i-simple-icons-visualstudiocode"}
Il est recommandé d'installer l'extension [Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss) pour VSCode et d'ajouter les paramètres suivants:

```json [.vscode/settings.json]
{
  "files.associations": {
    "*.css": "tailwindcss"
  },
  "editor.quickSuggestions": {
    "strings": "on"
  },
  "tailwindCSS.classAttributes": ["class", "ui"],
  "tailwindCSS.classFunctions": ["defineAppConfig"]
}
```

::

#### Enveloppez votre application avec le composant App

```vue [app.vue]
<template>
  <UApp>
    <NuxtPage />
  </UApp>
</template>
```

::note{to="/docs/components/app"}
Le composant `App` configure la configuration globale et est nécessaire pour **Toast**, **Tooltip** et **programmatic overlays**.
::

::

## options

Vous pouvez personnaliser l'interface utilisateur de Nuxt en fournissant des options dans votre `nuxt.config.ts`.

Xph192xx`prefix`

Utilisez l'option `prefix` pour modifier le préfixe des composants.

Par défaut: `U`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    prefix: 'Nuxt'
  }
})
```

### x`fonts`

Utilisez l'option `fonts` pour activer ou désactiver le module [`@nuxt/fonts`](https://github.com/nuxt/fonts).

- Par défaut: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    fonts: false
  }
})
```

### x`colorMode`

Utilisez l'option `colorMode` pour activer ou désactiver le module [`@nuxt/color-mode`](https://github.com/nuxt-modules/color-mode).

- Par défaut: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    colorMode: false
  }
})
```

### x`theme.colors`

Utilisez l'option `theme.colors` pour définir les alias de couleurs dynamiques utilisés pour générer le thème des composants.

Par défaut: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      colors: ['primary', 'error']
    }
  }
})
```

::note
Chaque alias génère un ensemble complet de nuances et de variantes `--ui-color-*` dans les thèmes de composants qui ont des variantes de couleur, que votre application l'utilise ou non. Coupez la liste aux alias que vous utilisez réellement et conservez `error` si vous utilisez des formulaires, car les styles de validation en dépendent.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
En savoir plus sur la personnalisation des couleurs et la thématisation dans la section Thème.
::

### x`theme.transitions`

Utilisez l'option `theme.transitions` pour activer ou désactiver les transitions sur les composants.

- Par défaut: `true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      transitions: false
    }
  }
})
```

::note
Cette option ajoute la classe `transition-colors` sur les composants avec des états stationnaires ou actifs.
::

### x`theme.unstyled`: badge{label="4.9+" class="align-text-top"}

Utilisez l'option `theme.unstyled` pour supprimer toutes les classes de thème par défaut des composants, en ne conservant que leur structure et les classes que vous fournissez via `class`, `ui` ou `app.config.ui`.

Par défaut: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      unstyled: true
    }
  }
})
```

::warning
Cela supprime également les classes **structural** (positionnement, transitions, flex/grille), pas seulement celles cosmétiques. Les composants lourds en termes de mise en page comme `Modal`, `Drawer` ou `Calendar` auront besoin de vous pour réapprovisionner leur mise en page, similaire au mode non stylé de PrimeVue.
::

### x`theme.defaultVariants`

Utilisez l'option `theme.defaultVariants` pour remplacer les variantes `color` et `size` par défaut pour les composants.

Seuls les paramètres par défaut qui sont exactement `primary` ou `md` sont remplacés, donc Avatar conserve `color: 'neutral'` et Separator conserve `size: 'xs'`.

Par défaut: `{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [nuxt.config.ts] {4-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      defaultVariants: {
        color: 'neutral',
        size: 'sm'
      }
    }
  }
})
```

### x`theme.prefix`: badge{label="4.2+" class="align-text-top"}

Utilisez l'option `theme.prefix` pour configurer le même préfixe que celui que vous avez défini sur votre importation CSS Tailwind. Cela garantit que les composants de l'interface utilisateur Nuxt utilisent les classes utilitaires et les variables CSS préfixées correctes.

::code-group

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  }
})
```

```css [app/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

::warning{to="https://fonts.nuxt.com/get-started/configuration#processcssvariables"}
Vous devrez peut-être activer `fonts.processCSSVariables` pour utiliser l'option de préfixe avec le module `@nuxt/fonts`:

```ts [nuxt.config.ts] {9-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  },
  fonts: {
    processCSSVariables: true
  }
})
```
::

Cela préfixe automatiquement toutes les classes d'utilitaires Tailwind et les variables CSS dans les thèmes de composants Nuxt UI:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
En savoir plus sur l'utilisation d'un préfixe dans la documentation CSS Tailwind.
::

### x`prose`

Utilisez l'option `prose` pour forcer l'importation des composants Nuxt UI [`Prose`)) même si `@nuxtjs/mdc`, `@nuxt/content` ou `@comark/nuxt` n'est pas installé.

Par défaut: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    prose: true
  }
})
```

### `mdc`: badge{label="Deprecated" color="warning" class="align-text-top"}

Utilisez l'option [`prose`](#prose) à la place.

### x`content`

Utilisez l'option `content` pour forcer l'importation des composants de prose et de contenu de l'interface utilisateur Nuxt, même si `@nuxt/content` n'est pas installé.

Par défaut: `false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    content: true
  }
})
```

### x`experimental.componentDetection`: badge{label="4.1+" class="align-text-top"}

Utilisez l'option `experimental.componentDetection` pour activer la détection automatique des composants pour le tree-shaking. Cette fonctionnalité analyse votre code source pour détecter les composants réellement utilisés et génère uniquement le CSS nécessaire pour ces composants (y compris leurs dépendances).

- Par défaut: `false`{lang="ts-type"}
Type de fichier: `boolean | string[]`{lang="ts-type"}

**Activer la détection automatique: **

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: true
    }
  }
})
```

**Inclure des composants supplémentaires pour une utilisation dynamique: **

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: ['Modal', 'DropdownMenu', 'Popover']
    }
  }
})
```

::note
Lorsque vous fournissez un tableau de noms de composants, la détection automatique est activée et ces composants (ainsi que leurs dépendances) sont garantis d'être inclus. Ceci est utile pour les composants dynamiques comme `<component :is="..." />` qui ne peuvent pas être analysés statiquement.
::

## Libération continue

Nuxt UI utilise [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new) pour les versions d'aperçu continues, offrant aux développeurs un accès instantané aux dernières fonctionnalités et corrections de bogues sans attendre les versions officielles.

Les versions d'aperçu automatiques sont créées pour tous les commits et les PR de la branche `v4`.Utilisez-les en remplaçant la version de votre paquet par le hachage de commit ou le numéro de PR.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new** commentera automatiquement les RP avec l'URL d'installation, ce qui facilite le test des modifications.
::
