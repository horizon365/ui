Nuxt UIは素晴らしいコミュニティのおかげで繁栄します❤️.このライブラリをより良くするために、バグレポート、プルリクエスト、フィードバックを通じたすべての貢献を歓迎します。

::caution
バグを報告したり、機能をリクエストしたりする前に、[ documentation ](https://ui.nuxt.com/)と既存の[ issues ](https://github.com/nuxt/ui/issues?q=is%3Aissue%20is%3Aopen%20sort%3Aupdated-desc)を読んでください。質問やヘルプについては、[ GitHub Discussions ](https://github.com/nuxt/ui/discussions/categories/q-a)をご利用ください。
::

##  AIアシスト

Nuxt UIへの貢献を支援するために、AIアシスタント向けに[`AGENTS.md`](https://github.com/nuxt/ui/blob/v4/AGENTS.md)を通じて貢献ガイドラインを提供しています。このガイドラインは、すべてのAIコーディングエージェントによって自動的にピックアップされ、コンポーネント構造、テーマパターン、テスト規約、ドキュメントガイドラインを通じてガイドされます。

## プロジェクト構造

Nuxt UIプロジェクト構造内の主要なディレクトリとファイルの概要は次のとおりです。

### ドキュメント

ドキュメントは`docs`フォルダにあり、`@nuxt/content`を使用してMarkdownファイルからページを生成するNuxtアプリです。どのように動作するかの詳細は[ Nuxt Content documentation ](https://content.nuxt.com/docs/getting-started)を参照してください。構造の内訳は次のとおりです。

```bash
├── app/
│   ├── assets/
│   ├── components/
│   │   └── content/
│   │       └── examples   # Components used in documentation as examples
│   ├── composables/
│   └── ...
├── content/
│   ├── blog/
│   ├── docs/
│   │   ├── 1.getting-started
│   │   ├── 2.components   # Components documentation
│   │   ├── 3.composables
│   │   └── 4.typography
│   └── ...            # Landing pages (index.yml, showcase.yml...)
```

### モジュール

モジュールコードは`src`フォルダにあります。以下はその構造の内訳です。

```bash
├── plugins/
├── runtime/
│   ├── components/        # Where all the components are located
│   │   ├── Accordion.vue
│   │   ├── Alert.vue
│   │   └── ...
│   ├── composables/
│   ├── locale/
│   ├── plugins/
│   ├── types/
│   ├── utils/
│   └── vue/
│       ├── components/
│       └── plugins/
├── theme/                 # This where the theme for each component is located
│   ├── accordion.ts       # Theme for Accordion component
│   ├── alert.ts
│   └── ...
├── utils/
└── module.ts
```

##  CLI

開発を容易にするために、コンポーネントとロケールの生成に使用できるCLIを作成しました。`pnpm cli make`コマンドを使用してアクセスできます。

### コンポーネント

次のコマンドを使用して新しいコンポーネントを作成できます。

```bash
pnpm cli make component <name> [options]
```

利用可能なオプション

- `--primitive`プリミティブコンポーネントを作成
- `--prose`散文コンポーネントを作成する
- `--content`コンテンツコンポーネントを作成します。
- `--template`特定のテンプレートのみを生成します（利用可能なテンプレート：`playground`、`docs`、`test`、`theme`、`component`）

例

```bash
# Create a basic component
pnpm cli make component my-component

# Create a prose component
pnpm cli make component heading --prose

# Create a content component
pnpm cli make component block --content

# Generate only documentation template
pnpm cli make component my-component --template=docs
```

::note
新しいコンポーネントを作成すると、CLIはコンポーネント自体、テーマ、テスト、ドキュメントなどの必要なすべてのファイルを自動的に生成します。
::

###  Locales

次のコマンドを使用して新しいロケールを作成できます。

```bash
pnpm cli make locale --code <code>
```

ロケール名と方向は[ CLDR ](https://cldr.unicode.org/)から入力され、コードはそれに対して検証されます。`--name`と`--dir`フラグで上書きできます。

メッセージを翻訳したら、次のように実行してロケールが他のロケール（メッセージキー、プレースホルダー、名前、方向）と一貫していることを確認できます。

```bash
pnpm test locale --run
```

::note{to="/docs/getting-started/integrations/i18n/nuxt#supported-languages"}
** i18n **について詳しくは、ドキュメントを参照してください。
::

## プルリクエスト（PR）を送信

作業を始める前に、作業中の問題または機能リクエストを説明する既存の問題がないか確認してください。存在する場合は、問題についてコメントを残して、作業中であることをお知らせください。

ない場合は、新しい問題を開いて問題や機能について議論してください。

### 地域開発

地域開発を始めるには、以下の手順に従う。

::steps{level="4"}

#### `nuxt/ui`リポジトリをローカルマシンにクローンします。

```bash
git clone -b v4 https://github.com/nuxt/ui.git
```

#### 有効化[ Corepack ](https://github.com/nodejs/corepack)

```bash
corepack enable
```

#### インストール依存関係

```bash
pnpm install
```

#### 型スタブを生成する

```bash
pnpm run dev:prepare
```

#### 開発開始

- `docs`フォルダにある** documentation **を操作するには、次のように実行します。

```bash
pnpm run docs
```

- ** playground **を使用してNuxtコンポーネントをテストするには、次のように実行します。

```bash
pnpm run dev
```

- ** playground **を使用してVueコンポーネントをテストするには、次のように実行します。

```bash
pnpm run dev:vue
```

::

::note{to="#cli"}
新しいコンポーネントの実装に取り組んでいる場合は、** CLI **セクションをチェックして、プロセスを開始してください。
::

###  IDEセットアップ

[ ESLint extension ](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint)と一緒にVSCodeを使用することをお勧めします。コードを保存するときに自動修正とフォーマットを有効にすることができます。方法は次のとおりです。

```json [.vscode/settings.json]
{
  "editor.codeActionsOnSave": {
    "source.fixAll": "never",
    "source.fixAll.eslint": "explicit"
  },
  "prettier.enable": false
}
```

::warning
ESLintは既にコードをフォーマットするように設定されていますので、** Prettier **で機能を複製する必要はありません。エディタにインストールされている場合は、競合を避けるために無効にすることをお勧めします。
::

### リンティング

`lint`コマンドを使用して、リンティングエラーを確認できます。

```bash
pnpm run lint # check for linting errors
pnpm run lint:fix # fix linting errors
```

### 型チェック

型チェックにはTypeScriptを使用します。`typecheck`コマンドを使用して型エラーをチェックできます。

```bash
pnpm run typecheck
```

### テスト

PRを送信する前に、テストを実行してください。

```bash
pnpm run test
```

::tip
スナップショットを更新する必要がある場合は、テストの実行が終了した後に`u`を押してください。
::

### コミット規約

コミットメッセージには[ Conventional Commits ](https://www.conventionalcommits.org/)を使用しています。これにより、コミットに基づいて変更履歴を自動生成できます。まだ慣れていない方は、[ guide ](https://www.conventionalcommits.org/en/v1.0.0/#summary)をお読みください。

- `fix`および`feat`を使用して、機能やロジックに影響を与えるコード変更
- ドキュメントの変更には`docs`を、メンテナンスタスクには`chore`を使用します。

### プルリクエストの作成

-  PR作成時に提供される[ instructions ](https://github.com/nuxt/ui/blob/v4/.github/PULL_REQUEST_TEMPLATE.md?plain=1)に従ってください

-  PRのタイトルが[ Conventional Commits ](https://www.conventionalcommits.org/)に準拠していることを確認してください。

- 複数のコミットは問題ありません。リベースや強制プッシュは必要ありません。マージ時には`Squash and Merge`を使用します。

- `lint`、`typecheck`、`tests`はPRを送信する前に動作します。無関係な変更は避けてください。

私たちは速やかにレビューします。メンテナに割り当てられた場合、彼らは慎重にレビューします。赤いテキストは無視してください。これは追跡目的です。
