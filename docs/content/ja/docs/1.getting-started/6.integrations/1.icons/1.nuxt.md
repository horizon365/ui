## 使用法

Nuxt UIは自動的に[`@nuxt/icon`](https://github.com/nuxt/icon)モジュールを登録しますので、追加のセットアップは必要ありません。

### アイコンコンポーネント

[ Icon ](/docs/components/icon)コンポーネントを`name` propで使用してアイコンを表示できます。

::component-code{slug="icon"}
---
小道具
  名前'i—lucide電球'
  クラス'サイズ—5'
---
::

::note
<https://iconify.design>コレクションから任意の名前を使用できます。<https://icones.js.org>で簡単に閲覧するか、[`search-icons`](/docs/getting-started/ai/mcp#available-tools) MCPツールを使用してAIアシスタントから直接検索します。
::

### コンポーネントプロップ

一部のコンポーネントには、[ Button ](/docs/components/button)のように、アイコンを表示するための`icon` propもあります。

::component-code{slug="button"}
---
無視
  - カラー
  - バリアント
小道具
  アイコンi—lucide太陽
  バリアント：微妙
スロット
  デフォルトボタン
---
::

## コレクション

###  Iconifyデータセット

アイコンデータをローカルにインストールすることを強くお勧めします。

::code-group{sync="pm"}

```bash [pnpm]
pnpm i @iconify-json/{collection_name}
```

```bash [yarn]
yarn add @iconify-json/{collection_name}
```

```bash [npm]
npm install @iconify-json/{collection_name}
```

::

たとえば、`i-uil-github`アイコンを使用するには、`@iconify-json/uil`でコレクションをインストールします。この方法でアイコンをローカルまたはサーバレス関数から提供することができ、SSRとクライアントサイドの両方でより高速で信頼性が高くなります。

コレクションをインストールすると、Nuxt UIが使用するアイコンをビルド時にクライアントバンドルに埋め込むことができます。そのため、実行時にオンデマンドでロードされるのではなく、最初のレンダリングで利用できます。これは、デフォルトで`lucide`コレクションからNuxt UI自身のアイコンに対して自動的に行われます。アプリの他の場所でオーバーライドしたり使用したりするアイコンなど、他のアイコンをバンドルするには、`@nuxt/icon`の[`clientBundle.icons`](https://github.com/nuxt/icon?tab=readme-ov-file#client-bundle)に追加してください。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      icons: ['lucide:heart', 'simple-icons:github']
    }
  }
})
```

または、`clientBundle.scan`を有効にして、ソースをスキャンしてアプリ全体で使用されているすべてのアイコンをバンドルします。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: true
    }
  }
})
```

スキャンは`.vue``.jsx``.tsx``.md``.mdc``.mdx``.yml``.yaml`ファイルのみを読み込み、文字列として書かれたアイコン名にのみマッチします。ナビゲーションリンクのリストのように、`.ts`または`.js`ファイルで定義されたアイコンは見逃されます。`i-lucide-${name}`のように動的に構築された名前も同様です。これらのファイルもスキャンするために`globInclude`を設定します。デフォルトのリストを置き換えるので、まだ必要な拡張子を残してください。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    clientBundle: {
      scan: {
        globInclude: ['**/*.{vue,jsx,tsx,md,mdc,mdx,yml,yaml,ts,js}']
      }
    }
  }
})
```

ビルド時にセット全体がわかっている場合でも、`clientBundle.icons`にリストすることで、動的な名前をバンドルすることができます。APIからのアイコンなど、実行時にのみ存在する名前はまったくバンドルすることはできません。アプリケーションがサーバーレンダリングされるときに`/api/_nuxt_icon`ルートからオンデマンドでロードされ、Iconify APIをフォールバックとして使用します。`nuxt generate`または`ssr: false`を使用した場合は、Iconify APIから直接アクセスできます。

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#iconify-dataset" target="_blank"}
詳細については、`@nuxt/icon`のドキュメントをご覧ください。
::

### カスタムローカルコレクション

ローカルSVGファイルを使用して、カスタムIconifyコレクションを作成できます。

たとえば、アイコンのSVGファイルを、`./app/assets/icons`のように、任意のフォルダの下に配置します。

```bash
assets/icons
├── add.svg
└── remove.svg
```

`nuxt.config.ts`に、`icon.customCollections`に項目を追加します。

```ts
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  icon: {
    customCollections: [{
      prefix: 'custom',
      dir: './app/assets/icons'
    }]
  }
})
```

次に、次のようにアイコンを使用できます：

```vue
<template>
  <UIcon name="i-custom-add" />
</template>
```

::note{to="https://github.com/nuxt/icon?tab=readme-ov-file#custom-local-collections" target="_blank"}
詳細については、`@nuxt/icon`のドキュメントを参照してください。
::
