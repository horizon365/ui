## Opstelling

### Toevoegen aan een Vue-project

::steps{level="4"}

#### Installeer het Nuxt UI-pakket

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Voeg de Nuxt UI Vite plugin in uw `vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI registreert `unplugin-auto-import` en `unplugin-vue-components`, die `auto-imports.d.ts` en `components.d.ts` type declaratiebestanden zal genereren. U zult waarschijnlijk willen gitignore deze, en voeg ze toe aan uw `tsconfig`.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
Deze declaratiebestanden worden alleen geschreven wanneer Vite wordt uitgevoerd.
Het standaard `create-vue` `build` script draait `vue-tsc` parallel met `vite build` (`run-p type-check "build-only {@}"`), dus bij een schone checkout kan typecontrole beginnen voordat de bestanden bestaan en mislukt met fouten zoals `Cannot find name 'useToast'`
. Voer in plaats daarvan de typecontrole uit na de build, zodat de verklaringen eerst worden gegenereerd.

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
Intern vertrouwt Nuxt UI op aangepaste aliassen om de thematypen op te lossen. Als u TypeScript gebruikt, voegt u deze aliassen toe aan uw `tsconfig`-bestanden om automatische aanvulling in uw `vite.config.ts` mogelijk te maken.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```
::

#### Gebruik de Nuxt UI Vue plugin

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

```ts [inertia/app/app.ts (AdonisJS Inertia)]{3,19}
import type { DefineComponent } from 'vue'
```

#### Voeg de klasse `isolate` toe aan uw rootcontainer

::code-group{sync="vite"}

```html [index.html (Vite)]{9}
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Nuxt UI</title>
  </head>
  <body>
    <div id="app" class="isolate"></div>
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

```blade [resources/views/app.blade.php (Laravel Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">
    @inertiaHead
    @vite('resources/js/app.ts')
  </head>
  <body>
    <div class="isolate">
        @inertia
    </div>
  </body>
</html>
```

```edge [resources/views/inertia_layout.edge (AdonisJS Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">
    @inertiaHead()
    @vite(['inertia/app/app.ts', `inertia/pages/${page.component}.vue`])
  </head>
  <body>
    @inertia({ class: 'isolate' })
  </body>
</html>
```

## Opties

U kunt Nuxt UI aanpassen door opties aan te bieden in uw `vite.config.ts`.

### `prefix`

Gebruik de optie `prefix` om het voorvoegsel van de componenten te wijzigen.

- Standaard: `U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

### `ui`

Gebruik de optie `ui` om configuratie voor Nuxt UI te bieden. Dit is het Vue-equivalent van de `ui`-sleutel in Nuxt 's `app.config.ts`.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

### `dts`

Gebruik de optie `dts` om het genereren van declaratiebestanden voor automatisch geïmporteerde componenten en composables in of uit te schakelen.

- Standaard: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

### `icon`

Gebruik de optie `icon` om standaard props in te stellen voor de [Icon](/docs/components/icon) component (`size`, `mode`, `customize`) en om build-time pictogrambundeling via `clientBundle` te configureren.
Bundelen van de eigen pictogrammen van Nuxt UI is standaard ingeschakeld wanneer hun verzameling is geïnstalleerd. Stel `clientBundle: false` in om af te zien.

- Standaard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
Lees meer over pictogramverzamelingen en clientbundeling in de **Icons**-documentatie.
::

### `colorMode`

Gebruik de optie `colorMode` om de integratie van de kleurmodus van `@vueuse/core` in of uit te schakelen.

- Standaard: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

### `theme.colors`

Gebruik de optie `theme.colors` om de dynamische kleuraliassen te definiëren die worden gebruikt om het componententhema te genereren.

- Standaard: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Elke alias genereert een volledige set `--ui-color-*`-tinten en varianten in de componentthema 's met kleurvarianten, of uw app deze nu gebruikt of niet.
Knip de lijst bij naar de aliassen die u daadwerkelijk gebruikt en bewaar `error` als u formulieren gebruikt, aangezien validatiestijlen erop vertrouwen.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Lees meer over kleuraanpassing en thema 's in de sectie Thema.
::

### `theme.transitions`

Gebruik de optie `theme.transitions` om overgangen op componenten in of uit te schakelen.

- Standaard: `true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
Deze optie voegt de klasse `transition-colors` toe aan componenten met zweef- of actieve toestanden.
::

### `theme.unstyled`: speelgoed{label="4.9+" class="align-text-top"}

Gebruik de optie `theme.unstyled` om alle standaard themaklassen uit componenten te verwijderen, waarbij alleen de structuur en de klassen die u via `class`, `ui` of `app.config.ui` aanbiedt behouden blijven.

- Standaard: `false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Dit verwijdert ook **structural** klassen (positionering, overgangen, flex / grid), niet alleen cosmetische.
Lay-out-zware componenten zoals `Modal`, `Drawer` of `Calendar` hebben je nodig om hun lay-out opnieuw te leveren, vergelijkbaar met de ongestyleerde modus van PrimeVue.
::

### `theme.defaultVariants`

Gebruik de optie `theme.defaultVariants` om de standaard `color`- en `size`-varianten voor componenten te overschrijven.

Alleen defaults die exact `primary` of `md` zijn worden vervangen, dus Avatar houdt `color: 'neutral'` en Separator houdt `size: 'xs'`.

- Standaard: `{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix`: badge{label="4.2+" class="align-text-top"}

Gebruik de optie `theme.prefix` om hetzelfde voorvoegsel te configureren dat u hebt ingesteld op uw Tailwind CSS-import. Dit zorgt ervoor dat Nuxt UI-componenten de juiste voorgeprogrammeerde hulpprogramma-klassen en CSS-variabelen gebruiken.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Dit zal automatisch alle Tailwind-nutsklassen en CSS-variabelen in Nuxt UI-componentthema 's prefixeren:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Lees meer over het gebruik van een voorvoegsel in de Tailwind CSS-documentatie.
::

### `prose`

Gebruik de optie `prose` om Nuxt UI [`Prose` components](/docs/typography) en hun thema in te schakelen.

- Standaard: `false`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prose: true
    })
  ]
})
```

### `autoImport`

Gebruik de optie `autoImport` om samenstelbare auto-import uit te schakelen of om [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import) opties aan te passen.

- Standaard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      autoImport: false
    })
  ]
})
```

::note
Indien uitgeschakeld, kunt u compositiebestanden nog steeds expliciet importeren vanuit `@nuxt/ui/composables`.
::

### `components`

Gebruik de optie `components` om automatisch importeren van componenten uit te schakelen of om [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components) aan te passen.

- Standaard: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      components: false
    })
  ]
})
```

::note
Indien uitgeschakeld, kunt u nog steeds componenten expliciet importeren, bijv. `import Button from '@nuxt/ui/components/Button.vue'` of `import ProseCode from '@nuxt/ui/components/prose/Code.vue'`.
::

### `router`: badge{label="4.3+" class="align-text-top"}

Gebruik de optie `router` om routeringsintegratie te configureren. Dit is handig voor toepassingen die geen `vue-router` gebruiken, zoals Electron-apps, MPA 's of frameworks zoals [Inertia.js](https://inertiajs.com/) of [Hybridly](https://hybridly.dev/).

- Standaard: `true`{lang="ts-type"}

| Waarde | Omschrijving |
| ----- | ----------- |
| `true`{lang="ts-type"} | Gebruikt `vue-router` voor navigatie met `RouterLink` component. |
| `false`{lang="ts-type"} | Schakelt routeringsintegratie uit, links worden weergegeven als gewone `<a>`-tags. |
| `'inertia'`{lang="ts-type"} | Gebruikt Inertia.js voor navigatie met zijn `Link`-component. |

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
U kunt aangepaste navigatielogica bieden voor frameworks zoals **Hybridly** door `router: false` in te stellen in de Vite-configuratie en een functie door te geven bij het installeren van de Vue-plug-in:

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
Wanneer ingesteld op `false` of `'inertia'`, is `vue-router` niet vereist als afhankelijkheid.
::

### `scanPackages`: badge{label="4.3+" class="align-text-top"}

Gebruik de optie `scanPackages` om extra npm-pakketten op te geven die moeten worden gescand op componenten met Nuxt UI. Dit is handig wanneer u een gedeelde componentenbibliotheek hebt die Nuxt UI gebruikt
 componenten intern.

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
Standaard wordt alleen `@nuxt/ui` gescand. Gebruik deze optie wanneer uw externe pakketten Vue-componenten bevatten die Nuxt UI gebruiken.
::

### `root`: badge{label="4.9+" class="align-text-top"}

Gebruik de optie `root` om de map te overschrijven waar Nuxt UI zijn `.nuxt-ui`-map genereert (met de themasjablonen).
Standaard gebruikt hij Vite 's `root`, maar in setups zoals [`electron-vite`](https://electron-vite.org/) wijst de `root` van de renderer naar een sub-directory (b.v. `src/renderer`), dus de templates landen in `src/renderer/node_modules/.nuxt-ui` waar Tailwind niet
 scannen, waardoor themaklassen als `bg-default`, `ring-default` en `divide-default` ontbreken.

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Richt `root` op je project root zodat de gegenereerde `.nuxt-ui` directory in een `node_modules` terechtkomt die Tailwind scant.
::

### `experimental.componentDetection`: badge{label="4.11+" class="align-text-top"}

Gebruik de optie `experimental.componentDetection` om automatische componentdetectie in te schakelen voor het schudden van bomen.
Deze functie scant uw broncode om te detecteren welke componenten daadwerkelijk worden gebruikt en genereert alleen de benodigde CSS voor die componenten (inclusief hun afhankelijkheden).
Zonder dit genereert de Vite-plug-in het thema CSS voor elk onderdeel.
Detectie omvat de Vite-root, de pakketten die worden vermeld in [`scanPackages`](#scanpackages) en elke `dirs` van de [`components`](#components) optie die zich buiten de root bevindt.

- Standaard: `false`{lang="ts-type"}
- Type: `boolean | string[]`{lang="ts-type"}

**Automatische detectie inschakelen: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**Inclusief extra componenten voor dynamisch gebruik: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Bij het verstrekken van een reeks componentnamen is automatische detectie ingeschakeld en worden deze componenten (samen met hun afhankelijkheden) gegarandeerd opgenomen.
Dit is handig voor dynamische componenten zoals `<component :is="..." />` die niet statisch kunnen worden geanalyseerd.
::

::warning
Nieuw gebruikte componenten worden opgepikt bij de volgende start van de dev-server. Als u een component toevoegt en de stijlen ontbreken, start u de dev-server opnieuw op.
::

## Continue versies

Nuxt UI gebruikt [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new) voor continue preview-releases, waardoor ontwikkelaars direct toegang hebben tot de nieuwste functies en bugfixes zonder te wachten op officiële releases.

Automatische preview-releases worden gemaakt voor alle commits en PR 's naar de `v4`-branch. Gebruik ze door uw pakketversie te vervangen door de specifieke commit-hash of PR-nummer.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new** zal automatisch reageren op PR 's met de installatie-URL, waardoor het gemakkelijk is om wijzigingen te testen.
::
