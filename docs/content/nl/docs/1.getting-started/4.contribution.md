## Projectstructuur

Hier is een overzicht van de belangrijkste mappen en bestanden in de Nuxt UI-projectstructuur:

### Documentation

De documentatie leeft in de `docs`-map als een Nuxt-app die `@nuxt/content` gebruikt om pagina 's uit Markdown bestanden te genereren. Zie de [Nuxt Content documentation](https://content.nuxt.com/docs/getting-started) voor details over hoe het werkt.
Hier is een overzicht van de structuur:

```bash
├── app/
│   ├── assets/
│   ├── components/
│   │   └── content/
│   │       └── examples   # Components used in documentation as examples
│   ├── composables/
│   └── ...
├── content/
│   ├── blog/
│   ├── docs/
│   │   ├── 1.getting-started
│   │   ├── 2.components   # Components documentation
│   │   ├── 3.composables
│   │   └── 4.typography
│   └── ...            # Landing pages (index.yml, showcase.yml...)
```

### Module

De modulecode bevindt zich in de `src`-map. Hier is een overzicht van de structuur:

```bash
├── plugins/
├── runtime/
│   ├── components/        # Where all the components are located
│   │   ├── Accordion.vue
│   │   ├── Alert.vue
│   │   └── ...
│   ├── composables/
│   ├── locale/
│   ├── plugins/
│   ├── types/
│   ├── utils/
│   └── vue/
│       ├── components/
│       └── plugins/
├── theme/                 # This where the theme for each component is located
│   ├── accordion.ts       # Theme for Accordion component
│   ├── alert.ts
│   └── ...
├── utils/
└── module.ts
```

## CLI

Om ontwikkeling gemakkelijker te maken, hebben we een CLI gemaakt die u kunt gebruiken om componenten en landinstellingen te genereren. U kunt deze openen met het `pnpm cli make`-commando.

### Componenten

U kunt nieuwe componenten maken met de volgende opdracht:

```bash
pnpm cli make component <name> [options]
```

Beschikbare opties:

- `--primitive` Een primitieve component maken
- `--prose` Een prozacomponent maken
- `--content` Een inhoudscomponent maken
- `--template` Genereer alleen een specifieke sjabloon (beschikbare sjablonen: `playground`, `docs`, `test`, `theme`, `component`)

Voorbeeld:

```bash
# Create a basic component
pnpm cli make component my-component

# Create a prose component
pnpm cli make component heading --prose

# Create a content component
pnpm cli make component block --content

# Generate only documentation template
pnpm cli make component my-component --template=docs
```

::note
Bij het maken van een nieuwe component genereert de CLI automatisch alle benodigde bestanden zoals de component zelf, het thema, tests en documentatie.
::

### Lokalen

U kunt nieuwe landinstellingen maken met de volgende opdracht:

```bash
pnpm cli make locale --code <code>
```

De locale naam en richting worden ingevuld vanuit [CLDR](https://cldr.unicode.org/) en de code wordt ertegen gevalideerd. Je kunt ze overschrijven met de `--name` en `--dir` vlaggen.

Nadat u de berichten hebt vertaald, kunt u controleren of uw landinstelling consistent blijft met de andere (berichtsleutels, tijdelijke aanduidingen, naam en richting) door het volgende uit te voeren:

```bash
pnpm test locale --run
```

::note{to="/docs/getting-started/integrations/i18n/nuxt#supported-languages"}
Meer informatie over **i18n** in de documentatie.
::

## Een Pull Request indienen (PR)

Controleer voordat u begint of er een bestaand probleem is dat het probleem of het functieverzoek beschrijft waaraan u werkt.
Als dat zo is, laat dan een reactie achter op het probleem om ons te laten weten dat u eraan werkt.

Als dat niet het geval is, opent u een nieuw probleem om het probleem of de functie te bespreken.

### Lokale ontwikkeling

Volg deze stappen om de lokale ontwikkeling te starten:

::steps{level="4"}

#### Clone de `nuxt/ui` repository naar uw lokale machine

```bash
git clone -b v4 https://github.com/nuxt/ui.git
```

####  [Corepack](https://github.com/nodejs/corepack) inschakelen

```bash
corepack enable
```

#### Afhankelijkheden installeren

```bash
pnpm install
```

#### Type stubs genereren

```bash
pnpm run dev:prepare
```

#### Start ontwikkeling

- Als u wilt werken op de **documentation** in de map `docs`, voert u het volgende uit:

```bash
pnpm run docs
```

- Voer het volgende uit om de Nuxt-componenten te testen met behulp van de **playground**:

```bash
pnpm run dev
```

- Voer het volgende uit om de Vue-componenten te testen met behulp van de **playground**:

```bash
pnpm run dev:vue
```

::

::note{to="#cli"}
Als u werkt aan de implementatie van een nieuw onderdeel, controleer dan de sectie **CLI** om het proces een kickstart te geven.
::

### IDE instellen

We raden het gebruik van VSCode naast de [ESLint extension](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint). U kunt auto-fix en opmaak inschakelen bij het opslaan van uw code. Hier is hoe:

```json [.vscode/settings.json]
{
  "editor.codeActionsOnSave": {
    "source.fixAll": "never",
    "source.fixAll.eslint": "explicit"
  },
  "prettier.enable": false
}
```

::warning
Aangezien ESLint al is geconfigureerd om de code te formatteren, is het niet nodig om functionaliteit te dupliceren met **Prettier**.
Als je het in je editor hebt geïnstalleerd, raden we je aan het uit te schakelen om conflicten te voorkomen.
::

### Linten

U kunt het `lint` commando gebruiken om te controleren op linting fouten:

```bash
pnpm run lint # check for linting errors
pnpm run lint:fix # fix linting errors
```

### Type het controleren

We gebruiken TypeScript voor typecontrole. U kunt het `typecheck` commando gebruiken om te controleren op typefouten:

```bash
pnpm run typecheck
```

### Testen

Voordat u een PR indient, moet u ervoor zorgen dat u de tests uitvoert:

```bash
pnpm run test
```

::tip
Als u de snapshots moet bijwerken, drukt u op `u` nadat de tests zijn uitgevoerd.
::

### Commit conventies

We gebruiken [Conventional Commits](https://www.conventionalcommits.org/) voor commit-berichten, waarmee een changelog automatisch kan worden gegenereerd op basis van de commits. Lees de [guide](https://www.conventionalcommits.org/en/v1.0.0/#summary) door als je er nog niet bekend mee bent.

- x`fix` en `feat` gebruiken voor codewijzigingen die van invloed zijn op functionaliteit of logica
- Gebruik `docs` voor documentatiewijzigingen en `chore` voor onderhoudstaken

### Een Pull Request maken

- Volg langs de [instructions](https://github.com/nuxt/ui/blob/v4/.github/PULL_REQUEST_TEMPLATE.md?plain=1) bij het maken van een PR

- Zorg ervoor dat de titel van uw PR voldoet aan de [Conventionele Commits](https://www.conventionalcommits.org/) omdat deze wordt gebruikt zodra de code is samengevoegd.

- Meerdere commits zijn prima; het is niet nodig om te rebasen of push te forceren. We gebruiken `Squash and Merge` bij het samenvoegen.

- Zorg ervoor dat `lint`, `typecheck` en `tests` werken voordat u de PR indient. Vermijd het aanbrengen van niet-gerelateerde wijzigingen.

We zullen het onmiddellijk bekijken. Indien toegewezen aan een onderhouder, zullen ze het zorgvuldig beoordelen. Negeer de rode tekst; het is voor trackingdoeleinden.
