### Añadir a un proyecto de Nuxt

::steps{level="4"}

#### Instalar el paquete de interfaz de usuario Nuxt

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Añadir el módulo de interfaz de usuario de Nuxt en su`nuxt.config.ts`{lang="ts-type"}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxt/ui']
})
```

::note
No es necesario añadir`@nuxt/icon`,`@nuxt/fonts`o`@nuxtjs/color-mode`a su matriz`modules`ya que Nuxt UI los registra automáticamente.Puede configurar estos módulos en su`nuxt.config.ts`utilizando las teclas`icon`,`fonts`y`colorMode`.
::

#### Import Tailwind CSS and Nuxt UI in your CSS

::code-group

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
```

```ts [nuxt.config.ts] {3}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css']
})
```

::

::tip{to="https://nuxt.com/docs/getting-started/layers" target="_blank"}
When using[Nuxt Layers](https://nuxt.com/docs/getting-started/layers), the module automatically generates[`@source`](https://tailwindcss.com/docs/functions-and-directives#source-directive)directives for each layer directory , ensuring Tailwind CSS scans all your layer source files for utility classes .
::

::callout{icon="i-simple-icons-visualstudiocode"}
It is recommended to install the[Tailwind CSS IntelliSense](https://marketplace.visualstudio.com/items?itemName=bradlc.vscode-tailwindcss)extension for VSCode and add the following settings :

```json [.vscode/settings.json]
{
  "files.associations": {
    "*.css": "tailwindcss"
  },
  "editor.quickSuggestions": {
    "strings": "on"
  },
  "tailwindCSS.classAttributes": ["class", "ui"],
  "tailwindCSS.classFunctions": ["defineAppConfig"]
}
```

::

#### Envuelva su aplicación con el componente App

```vue [app.vue]
<template>
  <UApp>
    <NuxtPage />
  </UApp>
</template>
```

::note{to="/docs/components/app"}
El componente`App`configura la configuración global y es necesario para**Toast**,**Tooltip**y**overlays**programática .
::

::

## Opciones

Puede personalizar la interfaz de usuario de Nuxt proporcionando opciones en su`nuxt.config.ts`.

@122 @@@ 123 @

Utilice la opción `prefix` para cambiar el prefijo de los componentes.

- Default:`U`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    prefix: 'Nuxt'
  }
})
```

@137 @@ 138 @

Utilice la opción `fonts` para activar o desactivar el módulo [`@nuxt/fonts`](https://github.com/nuxt/fonts).

- Default:`true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    fonts: false
  }
})
```

@157 @@ 158 @

Utilice la opción `colorMode` para activar o desactivar el módulo [`@nuxt/color-mode`](https://github.com/nuxt-modules/color-mode).

- Default:`true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-6}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    colorMode: false
  }
})
```

@177 @@ 178 @

Utilice la opción `theme.colors` para definir los alias de color dinámicos utilizados para generar el tema de los componentes.

- Default:`['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      colors: ['primary', 'error']
    }
  }
})
```

::note
Cada alias genera un conjunto completo de tonos y variantes de `--ui-color-*` en los temas de componentes que tienen variantes de color, ya sea que la aplicación lo use o no. Recorta la lista con los alias que realmente usa y mantén `error` si usa formularios, ya que los estilos de validación dependen de él.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Obtenga más información sobre la personalización del color y la tematización en la sección Tema.
::

@196@197

Utilice la opción `theme.transitions` para habilitar o deshabilitar las transiciones en los componentes.

- Default:`true`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      transitions: false
    }
  }
})
```

::note
Esta opción agrega la clase `transition-colors` a los componentes con estados de flotación o activos.
::

### `theme.unstyled`: Nombre del usuario: {label="4.9+" class="align-text-top"}

Utilice la opción `theme.unstyled` para eliminar todas las clases de tema predeterminadas de los componentes, manteniendo solo su estructura y las clases que proporcione a través de `class`,`ui` o `app.config.ui`.

- Default:`false`{lang="ts-type"}

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      unstyled: true
    }
  }
})
```

::warning
Esto elimina también las clases **structural**(posicionamiento, transiciones, flex/grid), no solo las cosméticas. Los componentes pesados en la disposición como `Modal`,`Drawer` o `Calendar` necesitarán que vuelva a suministrar su diseño, similar al modo sin estilo de PrimeVue.
::

@240 @@@ 241

Utilice la opción `theme.defaultVariants` para anular las variantes predeterminadas `color` y `size` para los componentes.

Sólo los valores predeterminados que son exactamente `primary` o `md` se sustituyen, por lo que Avatar mantiene `color: 'neutral'` y Separator mantiene `size: 'xs'`.

- Default :`{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [nuxt.config.ts] {4-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      defaultVariants: {
        color: 'neutral',
        size: 'sm'
      }
    }
  }
})
```

### `theme.prefix`: Nombre de usuario :{label="4.2+" class="align-text-top"}

Utilice la opción`theme.prefix`para configurar el mismo prefijo que estableció en su importación de Tailwind CSS . Esto garantiza que los componentes de la interfaz de usuario de Nuxt utilicen las clases de utilidad y las variables CSS prefijadas correctas .

::code-group

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  }
})
```

```css [app/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

::warning{to="https://fonts.nuxt.com/get-started/configuration#processcssvariables"}
Es posible que tenga que habilitar`fonts.processCSSVariables`para utilizar la opción de prefijo con el módulo`@nuxt/fonts`:

```ts [nuxt.config.ts] {9-11}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    theme: {
      prefix: 'tw'
    }
  },
  fonts: {
    processCSSVariables: true
  }
})
```
::

Esto prefijará automáticamente todas las clases de utilidad Tailwind y las variables CSS en los temas de componentes de interfaz de usuario de Nuxt :

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Obtenga más información sobre el uso de un prefijo en la documentación de Tailwind CSS .
::

### `experimental.componentDetection`: Nombre del usuario :{label="4.1+" class="align-text-top"}

Utilice la opción`experimental.componentDetection`para habilitar la detección automática de componentes para el tree-shaking . Esta función escanea su código fuente para detectar qué componentes se utilizan realmente y solo genera el CSS necesario para esos componentes (incluidas sus dependencias) .

- Default :`false`{lang="ts-type"}
- Nombre del usuario :`boolean | string[]`{lang="ts-type"}

**Habilitar la detección automática :**

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: true
    }
  }
})
```

Incluye componentes adicionales para uso dinámico :**

```ts [nuxt.config.ts] {4-8}
export default defineNuxtConfig({
  modules: ['@nuxt/ui'],
  css: ['~/assets/css/main.css'],
  ui: {
    experimental: {
      componentDetection: ['Modal', 'DropdownMenu', 'Popover']
    }
  }
})
```

::note
Cuando se proporciona una matriz de nombres de componentes , la detección automática está habilitada y estos componentes (junto con sus dependencias) están garantizados para ser incluidos.Esto es útil para componentes dinámicos como`<component :is="..." />`que no pueden ser analizados estáticamente .
::

## Liberaciones continuas

Nuxt UI utiliza el[pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)para versiones de vista previa continuas , proporcionando a los desarrolladores acceso instantáneo a las últimas características y correcciones de errores sin esperar a las versiones oficiales .

Se crean versiones de vista previa automáticas para todos los commits y PRs de la rama`v4`. Úsalos reemplazando la versión de su paquete con el hash de commit o el número de PR específico .

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
@@pH406@pkg.pr.new**comentará automáticamente los PR con la URL de instalación , lo que facilita la prueba de cambios .
::
