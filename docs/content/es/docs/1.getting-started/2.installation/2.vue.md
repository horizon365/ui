## Configuración

### Añadir a un proyecto Vue

::steps{level="4"}

#### Instalar el paquete Nuxt UI

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

::

#### Añadir el plugin Nuxt UI Vite en su `vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
La interfaz de usuario de Nuxt registra `unplugin-auto-import` y `unplugin-vue-components`, lo que generará archivos de declaración de tipo `auto-imports.d.ts` y `components.d.ts`.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
El script `create-vue` `build` por defecto ejecuta `vue-tsc` en paralelo con `vite build` (`run-p type-check "build-only {@}"`), por lo que en una comprobación de tipo de comprobación limpia puede comenzar antes de que los archivos existan y fallar con errores como `Cannot find name 'useToast'`.

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
Internamente, la interfaz de usuario de Nuxt se basa en alias personalizados para resolver los tipos de tema. Si está utilizando TypeScript, agregue estos alias a sus archivos `tsconfig` para habilitar la autofinalización en su `vite.config.ts`.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```
::

#### Use el complemento Nuxt UI Vue

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```


::code-group{sync="vite"}

```html [index.html (Vite)]{9}
  <head>
    <meta charset="UTF-8" />

  </head>

```

```blade [resources/views/app.blade.php (Laravel Inertia)]{10}
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">

    @vite('resources/js/app.ts')
  </head>
  <body>
    <div class="isolate">
        @inertia
    </div>
  </body>

```

```edge [resources/views/inertia_layout.edge (AdonisJS Inertia)]{10}
<!DOCTYPE html>
<html>
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1">

  </head>
  <body>
    @inertia({ class: 'isolate' })
  </body>
```

## Opciones

Puede personalizar la interfaz de usuario de Nuxt proporcionando opciones en su `vite.config.ts`.

### x`prefix` y

Use la opción `prefix` para cambiar el prefijo de los componentes.

- Default: `U`{lang="ts-type"} (en español)

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

### x`ui` (Edición española)

Utilice la opción `ui` para proporcionar la configuración de la interfaz de usuario de Nuxt. Este es el equivalente de Vue de la clave `ui` en `app.config.ts` de Nuxt.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

### x`dts`

Utilice la opción `dts` para habilitar o deshabilitar la generación de archivos de declaración para componentes y composibles importados automáticamente.

- Default: `true`x{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

### xx`icon` (Edición española)

Utilice la opción `icon` para establecer los accesorios predeterminados para el componente [Icon](/docs/components/icon) (`size`, `mode`, `customize`) y para configurar la agrupación de iconos en tiempo de compilación a través de `clientBundle`.

- Default: `{}`{lang="ts-type"} (en español)

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
Obtenga más información sobre las colecciones de iconos y la agrupación de clientes en la documentación de **Icons**.
::

### xx`colorMode` (Edición española)

Utilice la opción `colorMode` para habilitar o deshabilitar la integración del modo de color de `@vueuse/core`.

- Default: `true`{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

### x`theme.colors`

Utilice la opción `theme.colors` para definir los alias de color dinámicos utilizados para generar el tema de los componentes.

- Default: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"} (por defecto)

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Cada alias genera un conjunto completo de tonos y variantes `--ui-color-*` en los temas de componentes que tienen variantes de color, ya sea que la aplicación lo use o no. Recorte la lista a los alias que realmente usa y mantenga `error` si usa formularios, ya que los estilos de validación dependen de él.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Obtenga más información sobre la personalización del color y la tematización en la sección Tema.
::

### x`theme.transitions` (Edición española)

Utilice la opción `theme.transitions` para habilitar o deshabilitar las transiciones en los componentes.

- Default: `true`{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
Esta opción agrega la clase `transition-colors` a los componentes con estados de desplazamiento o activos.
::

### x`theme.unstyled` y badge{label="4.9+" class="align-text-top"}

Utilice la opción `theme.unstyled` para eliminar todas las clases de tema predeterminadas de los componentes, manteniendo solo su estructura y las clases que proporciona a través de `class`, `ui` o `app.config.ui`.

- Default: `false`{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Esto elimina también las clases **structural** (posicionamiento, transiciones, flex/grid), no solo las cosméticas.Los componentes pesados en la disposición como `Modal`, `Drawer` o `Calendar` necesitarán que vuelva a suministrar su diseño, similar al modo sin estilo de PrimeVue.
::

### xx`theme.defaultVariants` (Edición española)

Utilice la opción `theme.defaultVariants` para anular las variantes `color` y `size` predeterminadas para los componentes.

Sólo los valores predeterminados que son exactamente `primary` o `md` se sustituyen, por lo que Avatar mantiene `color: 'neutral'` y Separator mantiene `size: 'xs'`.

- Default: `{ color: 'primary', size: 'md' }`{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### x`theme.prefix` y badge{label="4.2+" class="align-text-top"}

Utilice la opción `theme.prefix` para configurar el mismo prefijo que configuró en su importación de Tailwind CSS. Esto garantiza que los componentes de la interfaz de usuario de Nuxt utilicen las clases de utilidad y las variables CSS prefijadas correctas.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Esto prefijará automáticamente todas las clases de utilidad Tailwind y las variables CSS en los temas de componentes de interfaz de usuario de Nuxt:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Obtenga más información sobre el uso de un prefijo en la documentación de Tailwind CSS.
::

### x`prose`

Utilice la opción `prose` para habilitar los componentes de Nuxt UI [`Prose`](/docs/typography) y su tema.

- Default: `false`x{lang="ts-type"} por defecto

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prose: true
    })
  ]
})
```

### x`autoImport` (Edición española)

Utilice la opción `autoImport` para deshabilitar las importaciones automáticas componibles o para personalizar las opciones de [`unplugin-auto-import`](https://github.com/unplugin/unplugin-auto-import).

- Default: `{}`{lang="ts-type"} (en inglés)

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      autoImport: false
    })
  ]
})
```

::note
Cuando está deshabilitado, todavía puede importar composables explícitamente desde `@nuxt/ui/composables`.
::

### x`components` (Edición española)

Utilice la opción `components` para deshabilitar las importaciones automáticas de componentes o para personalizar las opciones de [`unplugin-vue-components`](https://github.com/unplugin/unplugin-vue-components).

- xDefault: `{}`x{lang="ts-type"} por defecto

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      components: false
    })
  ]
})
```

::note
Cuando está desactivado, todavía puede importar componentes explícitamente, por ejemplo, `import Button from '@nuxt/ui/components/Button.vue'` o `import ProseCode from '@nuxt/ui/components/prose/Code.vue'`.
::

- Default: `true`x{lang="ts-type"} por defecto

| Valoración| Descripción|
| ----- | ----------- |
| `true`x{lang="ts-type"}| Utiliza `vue-router` para la navegación con el componente `RouterLink`.|
| `false`x{lang="ts-type"}| Deshabilita la integración de enrutamiento, los enlaces se renderizan como etiquetas `<a>` simples.|
| `'inertia'`xx{lang="ts-type"} (Edición española)| Utiliza Inertia.js para la navegación con su componente `Link`.|

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
Puede proporcionar una lógica de navegación personalizada para marcos como **Hybridly** configurando `router: false` en la configuración de Vite y pasando una función al instalar el complemento Vue:

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
Cuando se establece en `false` o `'inertia'`, `vue-router` no es necesario como dependencia.
::

### `scanPackages`: badge{label="4.3+" class="align-text-top"} (en inglés)

Utilice la opción `scanPackages` para especificar paquetes npm adicionales que deben analizarse en busca de componentes que utilicen la interfaz de usuario de Nuxt.

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
De forma predeterminada, solo se escanea `@nuxt/ui`.Utilice esta opción cuando sus paquetes externos contengan componentes de Vue que utilicen la interfaz de usuario de Nuxt.
::

### x`root`: badge{label="4.9+" class="align-text-top"}

Utilice la opción `root` para reemplazar el directorio donde Nuxt UI genera su directorio `.nuxt-ui` Por defecto utiliza `root` de Vite, pero en configuraciones como [`electron-vite`](https://electron-vite.org/) `root` del renderizador apunta a un subdirectorio.(por ejemplo, `src/renderer`), por lo que las plantillas aterrizan en `src/renderer/node_modules/.nuxt-ui` donde Tailwind no las escanea, lo que hace que falten clases de temas como `bg-default`, `ring-default` y `divide-default`.

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Apunte `root` a la raíz del proyecto para que el directorio `.nuxt-ui` generado termine en un `node_modules` que Tailwind escanea.
::

### `experimental.componentDetection`: badge{label="4.11+" class="align-text-top"}

Utilice la opción `experimental.componentDetection` para habilitar la detección automática de componentes para el tree-shaking. Esta función escanea su código fuente para detectar qué componentes se utilizan realmente y solo genera el CSS necesario para esos componentes.(incluyendo sus dependencias). Sin él, el plugin de Vite genera el tema CSS para cada componente. Detection cubre la raíz de Vite, Los paquetes listados en [`scanPackages`](#scanpackages) y cualquier `dirs` de la opción [`components`](#components) ubicada fuera de la raíz.

- Default: `false`x{lang="ts-type"} por defecto
Especificaciones: XPH900x{lang="ts-type"}

**Habilitar la detección automática: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**Incluir componentes adicionales para uso dinámico: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Cuando se proporciona una matriz de nombres de componentes, se habilita la detección automática y se garantiza que estos componentes (junto con sus dependencias) se incluirán. Esto es útil para componentes dinámicos como `<component :is="..." />` que no se pueden analizar estáticamente.
::

::warning
Los componentes recién utilizados se recogen en el siguiente inicio del servidor de desarrollo. Si agrega un componente y faltan sus estilos, reinicie el servidor de desarrollo.
::

## Liberaciones continuas.

La interfaz de usuario de Nuxt utiliza [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new) para versiones de vista previa continuas, proporcionando a los desarrolladores acceso instantáneo a las últimas funciones y correcciones de errores sin esperar a versiones oficiales.

Se crean versiones de vista previa automáticas para todos los commits y PRs de la rama `v4`.Utilízalos reemplazando la versión de tu paquete con el hash de commit o número de PR específico.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new** comentará automáticamente los PR con la URL de instalación, lo que facilita la prueba de cambios.
::
