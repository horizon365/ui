### Añadir a un proyecto de Vue

::steps{level="4"}

#### Instalar el paquete de interfaz de usuario Nuxt

::code-group{sync="pm"}

```bash [pnpm]
pnpm add @nuxt/ui tailwindcss
```

```bash [yarn]
yarn add @nuxt/ui tailwindcss
```

```bash [npm]
npm install @nuxt/ui tailwindcss
```

```bash [bun]
bun add @nuxt/ui tailwindcss
```

#### Agregue el plugin Nuxt UI Vite en su`vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI registra`unplugin-auto-import`y`unplugin-vue-components`, lo que generará archivos de declaración de tipo`auto-imports.d.ts`y`components.d.ts`. Es probable que desee gitignore estos , y añadirlos a su`tsconfig`.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
Estos archivos de declaración sólo se escriben cuando se ejecuta Vite . El script predeterminado`create-vue``build`ejecuta`vue-tsc`en paralelo con`vite build`(`run-p type-check "build-only {@}"`) , por lo que en una comprobación de tipo limpia puede comenzar antes de que los archivos existan y fallar con errores como`Cannot find name 'useToast'`. Ejecute la comprobación de tipo después de la compilación para que las declaraciones se generen primero .

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
Internamente , la interfaz de usuario de Nuxt se basa en alias personalizados para resolver los tipos de tema . Si está utilizando TypeScript , agregue estos alias a sus archivos`tsconfig`para habilitar la autofinalización en su`vite.config.ts`.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```

#### Use el plugin Nuxt UI Vue

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

## Opciones

Puede personalizar la interfaz de usuario de Nuxt proporcionando opciones en su`vite.config.ts`.

@389 @@ 390 @

Utilice la opción `prefix` para cambiar el prefijo de los componentes.

- Default:`U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

@@pH409 @

Utilice la opción `ui` para proporcionar la configuración de la interfaz de usuario de Nuxt. Este es el equivalente de Vue de la clave `ui` en la clave `app.config.ts` de Nuxt.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

@@pH433 @

Utilice la opción `dts` para habilitar o deshabilitar la generación de archivos de declaración para componentes y composiciones importados automáticamente.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

@453 @@ 454 @

Utilice la opción `icon` para establecer accesorios predeterminados para el componente [Icon](/docs/components/icon)(`size` y `mode`)`customize`) y para configurar la agrupación de iconos en tiempo de compilación a través de `clientBundle`. La agrupación de los iconos propios de Nuxt UI está habilitada de forma predeterminada cuando se instala su colección.`clientBundle: false` para excluirse.

- Default:`{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
Obtenga más información sobre las colecciones de iconos y la agrupación de clientes en la documentación de **Icons**.
::

@@pH489 @

Utilice la opción `colorMode` para habilitar o deshabilitar la integración del modo de color de `@vueuse/core`.

- Default:`true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

@510 @@ 511

Utilice la opción `theme.colors` para definir los alias de color dinámicos utilizados para generar el tema de los componentes.

- Default:`['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
Cada alias genera un conjunto completo de `--ui-color-*` tonos y variantes en los temas de componentes que tienen variantes de color, ya sea que la aplicación lo use o no. Recorta la lista a los alias que realmente usa y mantén `error` si usa formularios, ya que los estilos de validación dependen de él.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
Obtenga más información sobre la personalización del color y la temática en la sección Tema.
::

### `theme.unstyled`: Nombre del usuario: {label="4.9+" class="align-text-top"}

Utilice la opción `theme.unstyled` para eliminar todas las clases de tema predeterminadas de los componentes, manteniendo solo su estructura y las clases que proporcione a través de `class`,`ui` o `app.config.ui`.

- Default:`false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
Esto elimina también las clases **structural**(posicionamiento, transiciones, flex/grid), no solo las cosméticas. Los componentes pesados en la disposición como `Modal`,`Drawer` o `Calendar` necesitarán que vuelva a suministrar su diseño, similar al modo sin estilo de PrimeVue.
::

@@

Utilice la opción `theme.defaultVariants` para anular las variantes predeterminadas `color` y `size` de los componentes.

Sólo los valores predeterminados que son exactamente `primary` o `md` se sustituyen, por lo que Avatar mantiene `color: 'neutral'` y Separator mantiene `size: 'xs'`.

- Default:`{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix`: nombre de usuario {label="4.2+" class="align-text-top"}

Utilice la opción `theme.prefix` para configurar el mismo prefijo que estableció en su importación de Tailwind CSS. Esto garantiza que los componentes de la interfaz de usuario de Nuxt utilicen las clases de utilidad y las variables CSS prefijadas correctas.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

Esto prefijará automáticamente todas las clases de utilidad Tailwind y las variables CSS en los temas de componentes de interfaz de usuario de Nuxt:

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Obtenga más información sobre el uso de un prefijo en la documentación de Tailwind CSS.
::

### `router`: Nombre del usuario: {label="4.3+" class="align-text-top"}

Utilice la opción `router` para configurar la integración de enrutamiento. Esto es útil para aplicaciones que no utilizan `vue-router`, como aplicaciones Electron, MPAs o marcos como [Inertia.js](https://inertiajs.com/) o [Hybridly](https://hybridly.dev/).

- Default:`true`{lang="ts-type"}

| Valoración| Descripción|
| ----- | ----------- |
| @@@ph744@| Utiliza`vue-router`para la navegación con el componente`RouterLink`.|
| @@pH748@| Deshabilita la integración de enrutamiento , los enlaces se renderizan como etiquetas simples`<a>`.|
| @@ph751@@@ph753| Utiliza Inertia.js para la navegación con su componente`Link`.|

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
Puede proporcionar una lógica de navegación personalizada para marcos como**Hybridly**configurando`router: false`en la configuración de Vite y pasando una función al instalar el complemento Vue :

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
Cuando se establece en`false`o`'inertia'`,`vue-router`no es necesario como dependencia .
::

### `scanPackages`: Nombre del usuario :{label="4.3+" class="align-text-top"}

Utilice la opción`scanPackages`para especificar paquetes npm adicionales que deben analizarse en busca de componentes que utilicen Nuxt UI . Esto es útil cuando tiene una biblioteca de componentes compartida que utiliza componentes de Nuxt UI internamente .

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
De forma predeterminada , solo se escanea`@nuxt/ui`. Utilice esta opción cuando sus paquetes externos contengan componentes de Vue que utilicen la interfaz de usuario de Nuxt .
::

### `root`: Nombre del usuario :{label="4.9+" class="align-text-top"}

Utilice la opción`root`para anular el directorio donde Nuxt UI genera su directorio`.nuxt-ui`(que contiene las plantillas de tema) . Por defecto utiliza`root`de Vite , pero en configuraciones como[`electron-vite`](https://electron-vite.org/)el renderizador`root`apunta a un subdirectorio (por ejemplo ,`src/renderer`) , por lo que las plantillas aterrizan en`src/renderer/node_modules/.nuxt-ui`donde Tailwind no las escanea , lo que hace que falten clases de temas como`bg-default`,`ring-default`y`divide-default`.

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
Apunte`root`a la raíz de su proyecto para que el directorio`.nuxt-ui`generado termine en un`node_modules`que Tailwind escanea .
::

### `experimental.componentDetection`: nombre de usuario{label="4.11+" class="align-text-top"}

Utilice la opción`experimental.componentDetection`para habilitar la detección automática de componentes para el tree-shaking . Esta función escanea su código fuente para detectar qué componentes se utilizan realmente y solo genera el CSS necesario para esos componentes .(incluyendo sus dependencias) . Sin él , el plugin de Vite genera el tema CSS para cada componente . Detection cubre la raíz de Vite , Los paquetes enumerados en[`scanPackages`](#scanpackages)y cualquier`dirs`de la[`components`](#components)opción situada fuera de la raíz .

- Default :`false`{lang="ts-type"}
- Tipo :`boolean | string[]`{lang="ts-type"}

**Habilitar la detección automática :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

Incluye componentes adicionales para uso dinámico :**

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
Cuando se proporciona una matriz de nombres de componentes , se habilita la detección automática y se garantiza que estos componentes (junto con sus dependencias) se incluirán . Esto es útil para componentes dinámicos como`<component :is="..." />`que no se pueden analizar estáticamente .
::

::warning
Los componentes recién utilizados se recogen en el siguiente inicio del servidor de desarrollo . Si agrega un componente y faltan sus estilos , reinicie el servidor de desarrollo .
::

## Liberaciones continuas

Nuxt UI usa el[pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)para versiones de vista previa continuas , proporcionando a los desarrolladores acceso instantáneo a las últimas características y correcciones de errores sin esperar a las versiones oficiales .

Se crean versiones de vista previa automáticas para todos los commits y PRs de la rama`v4`. Úsalos reemplazando la versión de su paquete con el hash de commit específico o el número de PR.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
@@pH918@pkg.pr.new**comentará automáticamente los PR con la URL de instalación , lo que facilita la prueba de cambios .
::
