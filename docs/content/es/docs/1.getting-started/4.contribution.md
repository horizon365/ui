@@pH067@cli

Para facilitar el desarrollo, hemos creado una CLI que se puede utilizar para generar componentes y locales. Puede acceder a ella utilizando el comando `pnpm cli make`.

@@pH069@@Componentes

Puede crear nuevos componentes usando el siguiente comando:

```bash
pnpm cli make component <name> [options]
```

Opciones disponibles:

- `--primitive` Crear un componente primitivo
- `--prose` Crear un componente de prosa
- `--content` Crear un componente de contenido
- `--template` Sólo generar plantillas específicas (plantillas disponibles: `playground`,`docs`,`test`,`theme`,`component`)

Ejemplo:

```bash
# Create a basic component
pnpm cli make component my-component

# Create a prose component
pnpm cli make component heading --prose

# Create a content component
pnpm cli make component block --content

# Generate only documentation template
pnpm cli make component my-component --template=docs
```

::note
Al crear un nuevo componente, la CLI generará automáticamente todos los archivos necesarios como el componente en sí, el tema, las pruebas y la documentación.
::

@099@@Localidad

Puede crear nuevas ubicaciones usando el siguiente comando:

```bash
pnpm cli make locale --code <code>
```

El nombre de la localidad y la dirección se rellenan desde [CLDR](https://cldr.unicode.org/) y el código se valida contra él.

Una vez que haya traducido los mensajes, puede comprobar que su configuración regional se mantiene coherente con las demás (teclas de mensaje, marcadores de posición, nombre y dirección) ejecutando:

```bash
pnpm test locale --run
```

::note{to="/docs/getting-started/integrations/i18n/nuxt#supported-languages"}
Obtenga más información sobre **i18n** en la documentación.
::

## Enviar una solicitud de extracción (PR)

Antes de empezar, compruebe si hay un problema existente que describa el problema o la solicitud de función en la que está trabajando. Si lo hay, deje un comentario sobre el problema para hacernos saber que está trabajando en él.

Si no lo hay, abra un nuevo número para discutir el problema o la característica.

### Desarrollo Local

Para comenzar el desarrollo local, siga estos pasos:

::steps{level="4"}

#### Clonar el repositorio `nuxt/ui` a su máquina local

```bash
git clone -b v4 https://github.com/nuxt/ui.git
```

#### Enable [Corepack ](https://github.com/nodejs/corepack)

```bash
corepack enable
```

#### Instalar dependencias

```bash
pnpm install
```

#### Generar stubs de tipo

```bash
pnpm run dev:prepare
```

#### Inicio desarrollo

- Para trabajar en la **documentación** ubicada en la carpeta `docs`, ejecute:

```bash
pnpm run docs
```

- Para probar los componentes de Nuxt utilizando el **playground**, ejecute:

```bash
pnpm run dev
```

- Para probar los componentes de Vue utilizando el **playground**, ejecute:

```bash
pnpm run dev:vue
```

::

::note{to="#cli"}
Si está trabajando en la implementación de un nuevo componente, consulte la sección **CLI** para iniciar el proceso.
::

### Configuraciones

Recomendamos usar VSCode junto con la extensión [ESLint ](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint). Puede habilitar la corrección automática y el formato al guardar el código.

```json [.vscode/settings.json]
{
  "editor.codeActionsOnSave": {
    "source.fixAll": "never",
    "source.fixAll.eslint": "explicit"
  },
  "prettier.enable": false
}
```

::warning
Dado que ESLint ya está configurado para formatear el código, no hay necesidad de duplicar la funcionalidad con **Prettier**. Si lo tiene instalado en su editor, le recomendamos que lo deshabilite para evitar conflictos.
::

@175@Linting

Puede utilizar el comando `lint` para comprobar si hay errores de linting:

```bash
pnpm run lint # check for linting errors
pnpm run lint:fix # fix linting errors
```

### Tipo de verificación

Podemos utilizar TypeScript para la comprobación de tipos. Puede utilizar el comando `typecheck` para comprobar si hay errores de tipo:

```bash
pnpm run typecheck
```

@@ph186@Prueba de seguridad

Antes de enviar un PR, asegúrese de ejecutar las pruebas:

```bash
pnpm run test
```

::tip
Si tiene que actualizar las instantáneas, presione `u` después de que las pruebas hayan terminado de ejecutarse.
::

### Commit convenios

Usamos [Conventional Commits](https://www.conventionalcommits.org/) para los mensajes de confirmación, lo que permite que un registro de cambios se genere automáticamente en función de los commits.Por favor, lea la guía [](https://www.conventionalcommits.org/en/v1.0.0/#summary) a través de si aún no está familiarizado con ella.

- Use `fix` y `feat` para cambios de código que afectan la funcionalidad o la lógica
- Use `docs` para cambios en la documentación y `chore` para tareas de mantenimiento

### Haciendo una solicitud de extracción

- Siga las [instructions](https://github.com/nuxt/ui/blob/v4/.github/PULL_REQUEST_TEMPLATE.md?plain=1) proporcionadas al crear un PR

- Asegúrese de que el título de su PR se adhiera a los [Conventional Commits](https://www.conventionalcommits.org/) ya que se utilizará una vez que se fusione el código.

- Múltiples commits están bien; no hay necesidad de rebasar o forzar push.Usaremos `Squash and Merge` cuando fusionemos.

- Asegúrese de que `lint`,`typecheck` y `tests` trabajen antes de enviar la RP.

Lo revisaremos puntualmente. Si se asigna a un mantenedor, lo revisarán cuidadosamente. Ignore el texto rojo; es para fines de seguimiento.
