#### xx`vite.config.ts`{lang="ts-type"}에 Nuxt UI Vite 플러그인 추가

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::

::tip
Nuxt UI는 `unplugin-auto-import` 및 `unplugin-vue-components`를 등록하고 `auto-imports.d.ts` 및 `components.d.ts` 형식 선언 파일을 생성합니다. 이 파일을 gitignore하여 `tsconfig`에 추가하는 것이 좋습니다.

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
이러한 선언 파일은 vite가 실행될 때만 작성됩니다. 기본 `create-vue` `build` 스크립트는 `vue-tsc`를 `vite build` (`run-p type-check "build-only {@}"`)와 병렬로 실행하므로, 깨끗한 체크 아웃 유형 검사는 파일이 존재하기 전에 시작되고 `Cannot find name 'useToast'`와 같은 오류가 발생하여 실패합니다. 대신 빌드 후에 유형 검사를 실행하여 선언이 먼저 생성됩니다.

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
내부적으로 Nuxt UI는 사용자 정의 별칭을 사용하여 테마 유형을 확인합니다. TypeScript를 사용하는 경우 `tsconfig` 파일에 이러한 별칭을 추가하여 `vite.config.ts`에서 자동 완성을 가능하게 합니다.

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```

#### Nuxt UI Vue 플러그인 사용하기

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

## 옵션

`vite.config.ts`에서 옵션을 제공하여 Nuxt UI를 사용자 정의할 수 있습니다.

### `prefix` (### `prefix`)

`prefix` 옵션을 사용하여 구성 요소의 접두어를 변경합니다.

- Default: `U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

### `ui` (### `ui`)

`ui` 옵션을 사용하여 Nuxt UI에 대한 구성을 제공합니다. Nuxt의 `app.config.ts`에 있는 `ui` 키에 해당하는 Vue 기능입니다.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

### `dts` 공식

`dts` 옵션을 사용하여 자동으로 가져온 구성 요소 및 합성 파일에 대한 선언 파일 생성을 활성화하거나 비활성화합니다.

- 기본값: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

### `icon` 공식

`icon` 옵션을 사용하여 [Icon](/docs/components/icon) 구성 요소(`size`, `mode`, `customize`)에 대한 기본 소품을 설정하고 `clientBundle`를 통한 빌드 타임 아이콘 번들링을 구성합니다. Nuxt UI 자체 아이콘의 번들링은 기본적으로 설정되어 있습니다.

- Default: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
아이콘 컬렉션 및 클라이언트 번들에 대한 자세한 내용은 **Icons** 문서를 참조하십시오.
::

### `colorMode` (### `colorMode`)

`colorMode` 옵션을 사용하여 `@vueuse/core`의 색상 모드 통합을 활성화하거나 비활성화합니다.

- 기본값: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

### `theme.colors` (### `theme.colors`)

`theme.colors` 옵션을 사용하여 구성요소 주제를 생성하는 데 사용할 동적 색상 별칭을 정의합니다.

- 기본값: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
각 별칭은 구성 요소 테마에 `--ui-color-*` 음영 및 변형의 전체 집합을 생성하며, 응용 프로그램에서 사용하는지 여부에 관계없이 색상 변형이 있습니다. 목록을 실제 사용하는 별칭으로 잘라내고, 유효성 검사 스타일이 의존하므로 양식을 사용하는 경우에는 `error`를 유지합니다.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
테마 섹션에서 색상 사용자 정의 및 주제 지정에 대해 자세히 알아보십시오.
::

### `theme.transitions` 파일

`theme.transitions` 옵션을 사용하여 구성 요소의 전환을 활성화하거나 비활성화합니다.

- Default: `true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
이 옵션은 커서 또는 활성 상태가 있는 구성 요소에 `transition-colors` 클래스를 추가합니다.
::

### `theme.unstyled` : badge{label="4.9+" class="align-text-top"}

`theme.unstyled` 옵션을 사용하여 구성 요소에서 모든 기본 테마 클래스를 제거하고 해당 구조와 `class`, `ui` 또는 `app.config.ui`를 통해 제공된 클래스만 유지합니다.

- Default: `false`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        unstyled: true
      }
    })
  ]
})
```

::warning
이것은 **structural** 클래스 (포지셔닝, 전환, 플렉스 / 그리드)를 제거합니다.`Modal`, `Drawer` 또는 `Calendar`와 같은 레이아웃이 무거운 구성 요소는 PrimeVue의 스타일이 지정되지 않은 모드와 비슷한 레이아웃을 다시 공급해야합니다.
::

### `theme.defaultVariants` (### `theme.defaultVariants`)

`theme.defaultVariants` 옵션을 사용하여 구성 요소의 기본 `color` 및 `size` 변형을 재지정합니다.

정확히 `primary` 또는 `md`인 기본값만 대체되므로 아바타는 `color: 'neutral'`를 유지하고 분리기는 `size: 'xs'`를 유지합니다.

- Default: `{ color: 'primary', size: 'md' }`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        defaultVariants: {
          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix` : badge{label="4.2+" class="align-text-top"}

`theme.prefix` 옵션을 사용하여 Tailwind CSS 가져오기에서 설정한 것과 동일한 접두사를 구성합니다. 이렇게 하면 Nuxt UI 구성 요소가 올바른 접두사 유틸리티 클래스 및 CSS 변수를 사용할 수 있습니다.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

이것은 Nuxt UI 컴포넌트 테마의 모든 Tailwind 유틸리티 클래스와 CSS 변수에 자동으로 접두어를 추가합니다.

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Tailwind CSS 문서에서 접두사 사용에 대해 자세히 알아보십시오.
::

### `router` : badge{label="4.3+" class="align-text-top"} : badge{label="4.3+" class="align-text-top"}

`router` 옵션을 사용하여 라우팅 통합을 구성합니다. 이 옵션은 `vue-router`를 사용하지 않는 응용 프로그램(예: Electron 앱, MPA) 또는 ](Inertia.jshttps://inertiajs.com/) 또는 [Hybridly](xph74xxph75x와 같은 프레임워크)에 유용합니다.

- 기본값: `true`{lang="ts-type"}

| 가치 (Value)| 설명 (Description)|
| ----- | ----------- |
| `true`{lang="ts-type"} (`true`{lang="ts-type"})| `RouterLink` 구성 요소를 사용하여 탐색할 때 `vue-router`를 사용합니다.|
| `false`{lang="ts-type"} (`false`{lang="ts-type"})| 라우팅 통합을 비활성화하고 링크가 일반 `<a>` 태그로 렌더링됩니다.|
| `'inertia'`{lang="ts-type"}의 발음을 `'inertia'`xph788| Inertia.js를 사용하여 `Link` 구성 요소로 탐색합니다.|

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
Vite 설정에서 `router: false`를 설정하고 Vue 플러그인을 설치할 때 함수를 전달하여 **Hybridly**와 같은 프레임워크에 사용자 지정 탐색 로직을 제공할 수 있습니다.

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
`false` 또는 `'inertia'`로 설정하면 `vue-router`는 종속성으로 필요하지 않습니다.
::

### `scanPackages` : badge{label="4.3+" class="align-text-top"}

`scanPackages` 옵션을 사용하여 Nuxt UI를 사용하여 구성 요소를 검색해야 하는 추가 npm 패키지를 지정할 수 있습니다. 이 기능은 내부적으로 Nuxt UI 구성 요소를 사용하는 공유 구성 요소 라이브러리가 있는 경우 유용합니다.

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
기본적으로 `@nuxt/ui`만 스캔됩니다. 외부 패키지에 Nuxt UI를 사용하는 Vue 구성 요소가 포함되어 있을 때 이 옵션을 사용하십시오.
::

### `root` : badge{label="4.9+" class="align-text-top"}

`root` 옵션을 사용하여 Nuxt UI가 `.nuxt-ui` 디렉토리를 생성하는 디렉토리를 재정의합니다. 기본적으로 Viite의 `root`를 사용하지만, [`electron-vite`](https://electron-vite.org/)와 같은 설정에서는 렌더러의 `root`가 하위 디렉토리를 가리킵니다.(예를 들어 `src/renderer`) 템플릿이 `src/renderer/node_modules/.nuxt-ui`에 착륙하여 Tailwind가 스캔하지 않으므로 `bg-default`, `ring-default` 및 `divide-default`와 같은 테마 클래스가 누락됩니다.

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
프로젝트 루트에 `root`를 가리키면 생성된 `.nuxt-ui` 디렉토리가 Tailwind가 스캔하는 `node_modules`로 끝납니다.
::

### `experimental.componentDetection` : badge{label="4.11+" class="align-text-top"}

`experimental.componentDetection` 옵션을 사용하여 트리 셰이킹을 위한 자동 구성 요소 감지를 활성화합니다. 이 기능은 소스 코드를 스캔하여 실제로 사용되는 구성 요소를 감지하고 해당 구성 요소에 필요한 CSS만 생성합니다.(종속성 포함). 그것이 없으면, Vite 플러그인은 모든 구성요소에 대한 테마 CSS를 생성합니다. 탐지는 Vite 루트를 덮습니다. [`scanPackages`](#scanpackages)에 나열된 패키지와 루트 외부에 있는 [`components`](#components) 옵션의 `dirs`에 나열된 패키지입니다.

- Default: `false`{lang="ts-type"}
- Type : `boolean | string[]`{lang="ts-type"}

**자동 감지 기능 사용: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**동적 사용을 위한 추가 구성요소 포함: **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
구성 요소 이름 배열을 제공하면 자동 탐지가 활성화되고 이러한 구성 요소는 종속성과 함께 포함됩니다. 정적으로 분석할 수 없는 `<component :is="..." />`와 같은 동적 구성 요소에 유용합니다.
::

::warning
새로 사용된 구성 요소는 다음 dev-server 시작 시 선택됩니다. 구성 요소를 추가하고 해당 스타일이 누락된 경우 dev 서버를 다시 시작하십시오.
::

## Continuous 출시

Nuxt UI는 [pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)를 사용하여 지속적인 미리 보기 릴리스를 제공하므로 개발자가 공식 릴리스를 기다리지 않고도 최신 기능과 버그 수정에 즉시 액세스할 수 있습니다.

`v4` 분기에 대한 모든 커밋 및 PR에 대해 자동 미리 보기 릴리스가 생성됩니다. 패키지 버전을 특정 커밋 해시 또는 PR 번호로 대체하여 사용합니다.

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new**는 설치 URL을 사용하여 PR에 자동으로 주석을 추가하여 변경 사항을 쉽게 테스트할 수 있습니다.
::
