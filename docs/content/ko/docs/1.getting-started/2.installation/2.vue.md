####   Nuxt   UI   Vite   플러그인 을   추가  `vite.config.ts`{lang="ts-type"}

::code-group{sync="vite"}

```ts [vite.config.ts (Vite)]{3,8}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui()
  ]
})
```

```ts [vite.config.ts (Laravel Inertia)]{3,20-22}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import laravel from 'laravel-vite-plugin'

export default defineConfig({
  plugins: [
    laravel({
      input: ['resources/js/app.ts'],
      refresh: true
    }),
    vue({
      template: {
        transformAssetUrls: {
          base: null,
          includeAbsolute: false
        }
      }
    }),
    ui({
      router: 'inertia'
    })
  ]
})
```

```ts [vite.config.ts (AdonisJS Inertia)]{3,15-17}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import adonisjs from '@adonisjs/vite/client'
import inertia from '@adonisjs/inertia/client'

export default defineConfig({
  plugins: [
    adonisjs({
      entrypoints: ['inertia/app/app.ts'],
      reload: ['resources/views/**/*.edge']
    }),
    inertia(),
    vue(),
    ui({
      router: 'inertia'
    })
  ]
})
```

::tip
Nuxt   UI 는  `unplugin-auto-import`  및  `unplugin-vue-components`  을   등록 하 며  `auto-imports.d.ts`  및  `components.d.ts`  형식   선언   파일 을   생성 합니다 .   이   파일 들 을   gitignore 하 여  `tsconfig`  에   추가 하 는   것 이   좋 습니다 .

```json [tsconfig.app.json]
{
  "include": ["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue", "auto-imports.d.ts", "components.d.ts"]
}
```

```bash [.gitignore]
# Auto-generated type declarations
auto-imports.d.ts
components.d.ts
```

::

::warning
이러 한   선언   파일 은   Vite 가   실행 될   때 만   기록 됩니다 .   기본  `create-vue``build`스크립트 는  `vue-tsc`와  `vite build`  (`run-p type-check "build-only {@}"`) 와   병렬 로   실행 되 므로 ,   깨끗 한   체크   아웃   유형   검사 는   파일 이   존재 하 기   전 에   시작 되 고  `Cannot find name 'useToast'`와   같 은   오류 가   발생 합니다 .   빌드   후 에   유형   검사 를   실행 하 여   먼저   선언 을   생성 하 도록   합니다 .

```json [package.json]
{
  "scripts": {
    "build": "run-s build-only type-check"
  }
}
```

::

::tip
내부 적 으로   Nuxt   UI 는   사용자   정의   별칭 을   사용 하 여   테마   유형 을   분석 합니다 .   TypeScript 를   사용 하 는   경우  `tsconfig`  파일 에   이러 한   별칭 을   추가 하 여  `vite.config.ts`  내 에서   자동   완성 을   가능 하 게   합니다 .

```json [tsconfig.node.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui": [
        "./node_modules/.nuxt-ui/ui"
      ]
    }
  }
}
```

```json [tsconfig.app.json]
{
  "compilerOptions": {
    "paths": {
      "#build/ui/*": [
        "./node_modules/.nuxt-ui/ui/*"
      ]
    }
  }
}
```

#### Nuxt   UI   Vue   플러그인   사용

::code-group{sync="vite"}

```ts [src/main.ts (Vite)]{3,14}
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import ui from '@nuxt/ui/vue-plugin'
import App from './App.vue'

const app = createApp(App)

const router = createRouter({
  routes: [],
  history: createWebHistory()
})

app.use(router)
app.use(ui)

app.mount('#app')
```

```ts [resources/js/app.ts (Laravel Inertia)]{3,19}
import type { DefineComponent } from 'vue'
import { createInertiaApp } from '@inertiajs/vue3'
import ui from '@nuxt/ui/vue-plugin'
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers'
import { createApp, h } from 'vue'

const appName = import.meta.env.VITE_APP_NAME || 'Laravel x Nuxt UI'

createInertiaApp({
  title: title => (title ? `${title} - ${appName}` : appName),
  resolve: name =>
    resolvePageComponent(
      `./pages/${name}.vue`,
      import.meta.glob<DefineComponent>('./pages/**/*.vue')
    ),
  setup({ el, App, props, plugin }) {
    createApp({ render: () => h(App, props) })
      .use(plugin)
      .use(ui)
      .mount(el)
  }
})
```

##   옵션

`vite.config.ts`에   옵션 을   제공 하 여   Nuxt   UI 를   사용자   정의 할   수   있 습니다 .

### `prefix`

`prefix` 옵션을 사용하여 구성 요소의 접두사를 변경합니다.

- 기본값: `U`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      prefix: 'Nuxt'
    })
  ]
})
```

### `ui`

`ui` 옵션을 사용하여 Nuxt UI에 대한 설정을 제공합니다. 이것은 Nuxt의 `app.config.ts`에 있는 `ui` 키와 같은 Vue 값입니다.

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: 'green',
          neutral: 'slate'
        }
      }
    })
  ]
})
```

### `dts`

`dts` 옵션을 사용하여 자동으로 가져온 구성 요소 및 합성 파일에 대한 선언 파일 생성을 활성화하거나 비활성화합니다.

- 기본값: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      dts: false
    })
  ]
})
```

###  @ `icon` @

`icon` 옵션을 사용하여 [Icon](/docs/components/icon) 구성 요소에 대한 기본 소품을 설정합니다.(`size``mode` `mode`, `mode`, @ `mode`, @ `mode`, @ @ , `size`, @ @ , `mode`, @ , @ `mode`,`customize` ) 그리고 `clientBundle`를 통해 빌드 타임 아이콘 번들링을 설정합니다. Nuxt UI의 고유한 아이콘 번들링은 컬렉션이 설치될 때 기본적으로 활성화됩니다. @ @ @ 설정`clientBundle: false` 선택 해제

- 기본값: `{}`{lang="ts-type"}

```ts [vite.config.ts] {9-14}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      icon: {
        mode: 'svg',
        clientBundle: {
          scan: true
        }
      }
    })
  ]
})
```

::note{to="/docs/getting-started/integrations/icons/vue#collections"}
아이콘 컬렉션 및 클라이언트 번들에 대한 자세한 내용은 **Icons** 문서를 참조하십시오.
::

### `colorMode`

`colorMode` 옵션을 사용하여 `@vueuse/core`에서 색상 모드 통합을 활성화 또는 비활성화합니다.

- 기본값: `true`{lang="ts-type"}

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      colorMode: false
    })
  ]
})
```

### `theme.colors` @ `theme.colors` @

`theme.colors` 옵션을 사용하여 구성요소 주제를 생성하는 데 사용되는 동적 색상 별칭을 정의합니다.

- 기본값: `['primary', 'secondary', 'success', 'info', 'warning', 'error']`{lang="ts-type" class="inline"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        colors: ['primary', 'error']
      }
    })
  ]
})
```

::note
각 별칭은 구성 요소 테마에서 사용 여부에 관계없이 `--ui-color-*`shades 및 변형의 전체 집합을 생성합니다. 실제 사용 중인 별칭으로 목록을 잘라내고 유효성 검사 스타일에 의존하기 때문에 양식을 사용하는 경우 `error`을 유지합니다.
::

::tip{to="/docs/getting-started/theme/design-system#color-system"}
테마 섹션에서 색상 사용자화 및 주제 지정에 대해 자세히 알아보십시오.
::

###  @ `theme.transitions`

`theme.transitions` 옵션을 사용하여 구성 요소의 전환을 활성화하거나 비활성화합니다.

- 기본값: `true`{lang="ts-type"}

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        transitions: false
      }
    })
  ]
})
```

::note
이 옵션은 커서 또는 활성 상태가 있는 구성 요소에 `transition-colors` 클래스를 추가합니다.
::

### `theme.unstyled` @ `theme.unstyled` @ badge{label="4.9+" class="align-text-top"}

`theme.unstyled` 옵션을 사용하여 구성 요소에서 모든 기본 테마 클래스를 제거하고 해당 구조와 `class`, `ui` 또는 `app.config.ui`를 통해 제공한 클래스만 유지합니다.

### `theme.defaultVariants` @ `theme.defaultVariants` @

`theme.defaultVariants` 옵션을 사용하여 구성 요소의 기본 `color` 및 `size` 변형을 재정의합니다.

정확히 `primary` 또는 `md`인 기본값만 대체되므로 Avatar는 `color: 'neutral'`를 유지하고 Separator는 `size: 'xs'`을 유지합니다.

```ts [vite.config.ts] {9-14}
export default defineConfig({

    vue(),
    ui({

          color: 'neutral',
          size: 'sm'
        }
      }
    })
  ]
})
```

### `theme.prefix` badge {label="4.2+" class="align-text-top"}

`theme.prefix` 옵션을 사용하여 Tailwind CSS 가져오기에서 설정한 것과 동일한 접두사를 구성합니다. 이렇게 하면 Nuxt UI 구성 요소가 올바른 접두사 유틸리티 클래스와 CSS 변수를 사용할 수 있습니다.

::code-group

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      theme: {
        prefix: 'tw'
      }
    })
  ]
})
```

```css [src/assets/css/main.css] {1}
@import "tailwindcss" prefix(tw);
@import "@nuxt/ui";
```

::

이것은 Nuxt UI 컴포넌트 테마의 모든 Tailwind 유틸리티 클래스와 CSS 변수에 자동으로 접두어를 추가합니다.

```html
<!-- Without prefix -->
<button class="px-2 py-1 text-xs hover:bg-primary/75">Button</button>

<!-- With prefix: tw -->
<button class="tw:px-2 tw:py-1 tw:text-xs tw:hover:bg-primary/75">Button</button>
```

::note{to="https://tailwindcss.com/docs/styling-with-utility-classes#using-the-prefix-option" target="_blank"}
Tailwind CSS 문서에서 접두사 사용에 대해 자세히 알아보십시오.
::

### `router` `router` badge{label="4.3+" class="align-text-top"}

`router` 옵션을 사용하여 라우팅 통합을 구성합니다. 전자 앱, MPA와 같이 `vue-router`를 사용하지 않는 응용 프로그램이나 [Inertia.js](https://inertiajs.com/) 또는 [Hybridly{label="4.3+" class="align-text-top"}{label="4.3+" class="align-text-top"}{label="4.3+" class="align-text-top"} 같은 프레임워크에 유용합니다.

- 기본값: `true`{lang="ts-type"}

| 가치 (Value)| 설명 (Description)|
| ----- | ----------- |
| `true`{lang="ts-type"}| `vue-router`를   사용 하 여  `RouterLink`  구성 요소 를   탐색 합니다 .|
| `false` @ {lang="ts-type"}| 라우팅   통합 을   비 활성 화 하 고   링크 는   일반  `<a>`  태그 로   렌더링 됩니다 .|
| `'inertia'`{lang="ts-type"}| Inertia . js 를   사용 하 여  `Link`  구성   요소 로   탐색 합니다 .|

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      router: false
    })
  ]
})
```

::tip
Vite   설정 에서  **Hybridly**  을   설정 하 고   Vue   플러그인 을   설치 할   때   함수 를   전달 하 여  **와   같 은   프레임워크 에   사용자   지정   탐색   로직 을   제공 할   수   있 습니다 :

```ts [src/main.ts]
import ui from '@nuxt/ui/vue-plugin'
import { router } from 'hybridly'

app.use(ui, {
  router: (event, { href, external }) => {
    if (external) {
      return
    }

    event.preventDefault()

    router.navigate({ url: href })
  }
})
```
::

::note
`false`  또는  `'inertia'`로   설정 하 면  `vue-router`  종속 성 으로   필요 하 지   않 습니다 .
::

### `scanPackages` `scanPackages`  badge{label="4.3+" class="align-text-top"}

`scanPackages`  옵션 을   사용 하 여   Nuxt   UI 를   사용 하 여   구성   요소 를   검색 해야   하 는   추가   npm   패키지 를   지정 합니다 .   이   기능 은   내부 적 으로   Nuxt   UI   구성   요소 를   사용 하 는   공유   구성   요소   라이브러리 가   있 는   경우   유용 합니다 .

```ts [vite.config.ts] {9}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      scanPackages: ['@my-org/ui-components']
    })
  ]
})
```

::note
기본 적 으로  `@nuxt/ui`  만   스캔 됩니다 .   외부   패키지 에   Nuxt   UI 를   사용 하 는   Vue   구성   요소 가   포함 되 어   있 을   때   이   옵션 을   사용 하 십시오 .
::

### `root`badge{label="4.9+" class="align-text-top"}

`root`  옵션 을   사용 하 여   Nuxt   UI 가  `.nuxt-ui`  디렉 토리 를   생성 하 는   디렉 토리 를   재 정의 합니다 .(테마   템플 릿   포함) .   기본 적 으로   Viite 의  `root`를   사용 합니다 . 하지만  [`electron-vite`](https://electron-vite.org/)렌 더러 의  `root`와   같 은   설정 에서 는   하위   디렉 토리 를   가리킵니다 .(예 를   들 어  `src/renderer`)   템플 릿 이  `src/renderer/node_modules/.nuxt-ui`에   저장 되 어   Tailwind 가   스캔 하 지   않 으므로  `bg-default`,  `ring-default`  및  `divide-default`와   같 은   테마   클래스 가   누락 됩니다 .

```ts [electron.vite.config.ts] {12}
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  renderer: {
    root: 'src/renderer',
    plugins: [
      vue(),
      ui({
        root: __dirname
      })
    ]
  }
})
```

::note
프로젝트   루트 에서  `root`를   점 하 면   생성 된  `.nuxt-ui`  디렉 토리 는   Tailwind   스캔 에서  `node_modules`로   끝 납니다 .
::

### `experimental.componentDetection` @ `experimental.componentDetection` @  badge{label="4.11+" class="align-text-top"}

`experimental.componentDetection`  옵션 을   사용 하 여   트리   셰이킹 을   위한   자동   구성 요소   감지 를   활성 화 합니다 .   이   기능 은   소스   코드 를   스캔 하 여   실제로   사용 되 는   구성 요소 를   감지 하 고   해당   구성 요소 에   필요 한   CSS 만   생성 합니다 .(종속 성   포함) .   그것 이   없 으면 ,   Vite   플러그인 은   모든   구성 요소 에   대한   테마   CSS 를   생성 합니다 .   탐지 는   Vite   루트 를   덮 습니다 . 패키지 는  [`scanPackages`](#scanpackages)  및   임의 의  `dirs` @ [`components`]( #components  옵션 에서   루트   외부 에   있 습니다 .

- 기본 값 :  `false`{lang="ts-type"}
- 유형 :`boolean | string[]`{lang="ts-type"}

**자동   감지   사용 :  **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: true
      }
    })
  ]
})
```

**동적   사용 을   위한   추가   구성 요소   포함 :  **

```ts [vite.config.ts] {9-11}
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      experimental: {
        componentDetection: ['Modal', 'DropdownMenu', 'Popover']
      }
    })
  ]
})
```

::note
구성   요소   이름 의   배열 을   제공 하 면   자동   탐지 가   활성 화 되 고   이러 한   구성   요소 는   종속 성 과   함께   포함 됩니다 .   정적 으로   분석 할   수   없 는  `<component :is="..." />`와   같 은   동적   구성   요소 에   유용 합니다 .
::

::warning
새로   사용 된   구성   요소 는   다음   dev - server   시작   시   선택 됩니다 .   구성   요소 를   추가 하 고   해당   스타일 이   누락 된   경우   dev   서버 를   다시   시작 하 십시오 .
::

##   지속 적 인   발표

Nuxt   UI 는  [를   사용 합니다pkg.pr.new](https://github.com/stackblitz-labs/pkg.pr.new)  지속 적 인   미리 보 기   릴리스 를   제공 하 여   개발자 가   공식   릴리스 를   기다리 지   않 고 도   최신   기능 과   버그   수정 을   즉시   액세스 할   수   있 습니다 .

모든   커밋   및   PR 에   대해   자동   미리   보 기   릴리스 가  `v4`branch 에   생성 됩니다 .   패키지   버전 을   특정   커밋   해시   또는   PR   번호 로   대체 하 여   사용 합니다 .

```diff [package.json]
{
  "dependencies": {
-   "@nuxt/ui": "^4.0.0",
+   "@nuxt/ui": "https://pkg.pr.new/@nuxt/ui@4c96909",
  }
}
```

::note
**pkg.pr.new**는   자동 으로   PR 에   주석 을   달 아   설치   URL 을   사용 하 여   변경   사항 을   쉽 게   테스트   할   수   있 습니다 .
::
