## AI 지원

당사는 [`AGENTS.md`](https://github.com/nuxt/ui/blob/v4/AGENTS.md)를 통해 AI 비서가 Nuxt UI에 기여하는 데 도움을 줄 수 있도록 기여 지침을 제공합니다. 모든 AI 코딩 에이전트와 가이드가 구성요소 구조, 주제 지정 패턴, 테스트 규칙 및 문서 지침을 통해 자동으로 선택합니다.

## 프로젝트 구성

다음은 Nuxt UI 프로젝트 구조의 키 디렉토리 및 파일에 대한 개요입니다.

###  파일

문서는 `docs` 폴더에 있는 Nuxt 앱으로 `@nuxt/content` 폴더에 있으며 Markdown 파일에서 페이지를 생성합니다. [Nuxt Content documentation](https://content.nuxt.com/docs/getting-started)를 참조하십시오. 작동 방식에 대한 자세한 내용은 다음과 같습니다.

```bash
├── app/
│   ├── assets/
│   ├── components/
│   │   └── content/
│   │       └── examples   # Components used in documentation as examples
│   ├── composables/
│   └── ...
├── content/
│   ├── blog/
│   ├── docs/
│   │   ├── 1.getting-started
│   │   ├── 2.components   # Components documentation
│   │   ├── 3.composables
│   │   └── 4.typography
│   └── ...            # Landing pages (index.yml, showcase.yml...)
```

###  모듈

모듈 코드는 `src` 폴더에 있습니다. 다음은 해당 구조에 대한 분석입니다.

```bash
├── plugins/
├── runtime/
│   ├── components/        # Where all the components are located
│   │   ├── Accordion.vue
│   │   ├── Alert.vue
│   │   └── ...
│   ├── composables/
│   ├── locale/
│   ├── plugins/
│   ├── types/
│   ├── utils/
│   └── vue/
│       ├── components/
│       └── plugins/
├── theme/                 # This where the theme for each component is located
│   ├── accordion.ts       # Theme for Accordion component
│   ├── alert.ts
│   └── ...
├── utils/
└── module.ts
```

##  CLI

개발을 더욱 쉽게 하기 위해 구성 요소와 로케일을 생성하는 데 사용할 수 있는 CLI를 만들었습니다.`pnpm cli make` 명령을 사용하여 액세스할 수 있습니다.

###  구성 요소

다음 명령을 사용하여 새 구성요소를 생성할 수 있습니다.

```bash
pnpm cli make component <name> [options]
```

사용 가능한 옵션:

- `--primitive`기본 구성요소 작성
- `--prose`산문 구성 요소 만들기
- `--content`콘텐츠 구성요소 생성
- `--template`특정 템플릿만 생성합니다(사용 가능한 템플릿: `playground`, `docs`, `test`, `theme`, `component`)

예를 들면 다음과 같습니다.

```bash
# Create a basic component
pnpm cli make component my-component

# Create a prose component
pnpm cli make component heading --prose

# Create a content component
pnpm cli make component block --content

# Generate only documentation template
pnpm cli make component my-component --template=docs
```

::note
새 구성 요소를 생성할 때 CLI는 구성 요소 자체, 테마, 테스트 및 설명서와 같은 필요한 모든 파일을 자동으로 생성합니다.
::

###  로켈 레스

다음 명령을 사용하여 새 로켈을 만들 수 있습니다.

```bash
pnpm cli make locale --code <code>
```

로케일 이름과 방향은 [CLDR](https://cldr.unicode.org/)에서 입력되며 코드는 이와 비교하여 검증됩니다. `--name` 및 `--dir` 플래그를 사용하여 재정의할 수 있습니다.

메시지를 번역한 후에는 다음을 실행하여 로케일이 다른 것들과 일치하는지 확인할 수 있습니다(메시지 키, 자리 표시자, 이름 및 방향).

```bash
pnpm test locale --run
```

::note{to="/docs/getting-started/integrations/i18n/nuxt#supported-languages"}
문서에서 **i18n**에 대한 자세한 내용을 알아보십시오.
::

##  Pull Request(PR) 제출

시작하기 전에 현재 진행 중인 문제나 기능 요청을 설명하는 기존 문제가 있는지 확인하십시오. 문제가 있으면 문제에 대한 의견을 남겨 주시고 문제에 대해 작업 중이라는 것을 알려 주십시오.

문제가 없는 경우 새 문제를 열어 문제 또는 기능에 대해 논의합니다.

### 지역 개발

로컬 개발을 시작하려면 다음 단계를 수행하십시오.

::steps{level="4"}

#### 로컬 시스템에 `nuxt/ui`저장소 복제

```bash
git clone -b v4 https://github.com/nuxt/ui.git
```

####  활성 화 [ Corepack ](https://github.com/nodejs/corepack)

```bash
corepack enable
```

####  종속성 설치

```bash
pnpm install
```

####  유형 스텁 생성

```bash
pnpm run dev:prepare
```

####  개발 시작

-  @ **documentation@@ 폴더에 있는 ** 작업하려면 다음을 실행합니다.

```bash
pnpm run docs
```

-  @ **playground** 를 사용하여 Nuxt 구성 요소를 테스트하려면 다음을 실행합니다.

```bash
pnpm run dev
```

-  @ **playground** 를 사용하여 Vue 구성 요소를 테스트하려면 다음을 실행합니다.

```bash
pnpm run dev:vue
```

::

::note{to="#cli"}
새 구성 요소를 구현하는 작업을 하고 있다면 **CLI** 섹션을 확인하여 프로세스를 시작하십시오.
::

### IDE 설치

VSCode를 [ESLint extension](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint)와 함께 사용하는 것이 좋습니다. 코드를 저장할 때 자동 수정 및 포맷을 사용할 수 있습니다. 다음은 다음과 같습니다.

```json [.vscode/settings.json]
{
  "editor.codeActionsOnSave": {
    "source.fixAll": "never",
    "source.fixAll.eslint": "explicit"
  },
  "prettier.enable": false
}
```

::warning
ESLint는 이미 코드를 포맷하도록 구성되어 있으므로 **Prettier**로 기능을 중복할 필요가 없습니다. 편집기에 설치되어 있다면 충돌을 방지하기 위해 비활성화하는 것이 좋습니다.
::

###  Linting

`lint` 명령을 사용하여 Linting 오류를 확인할 수 있습니다.

```bash
pnpm run lint # check for linting errors
pnpm run lint:fix # fix linting errors
```

### 유형 검사

TypeScript를 사용하여 타입 검사를 합니다. `typecheck` 명령을 사용하여 타입 오류를 확인할 수 있습니다:

```bash
pnpm run typecheck
```

###  테스트

PR을 제출하기 전에, 테스트를 실행해야 합니다.

```bash
pnpm run test
```

::tip
스냅샷을 업데이트해야 하는 경우 테스트 실행이 완료된 후 `u`를 누르십시오.
::

###  공약 제출

커밋 메시지에는 [Conventional Commits](https://www.conventionalcommits.org/)를 사용하여 변경 로그를 커밋에 따라 자동으로 생성할 수 있습니다. 아직 익숙하지 않은 경우 [guide](https://www.conventionalcommits.org/en/v1.0.0/#summary)through를 읽어 주십시오.

-  기능 또는 논리에 영향을 미치는 코드 변경에 대해 `fix` 및 `feat`를 사용합니다.
- 문서 변경에는 `docs`를 사용하고 유지 관리 작업에는 `chore`를 사용합니다.

###  Pull Request 요청 만들기

- PR을 만들 때 제공되는 [Instructions](https://github.com/nuxt/ui/blob/v4/.github/PULL_REQUEST_TEMPLATE.md?plain=1)을 따라 가십시오.

-  귀하의 PR 제목이 코드가 병합되면 사용될 것이므로 [Conventional Commits](https://www.conventionalcommits.org/)을 준수하도록 하십시오.

-  여러 커밋이 괜찮습니다. 재베이스 또는 강제 푸시가 필요하지 않습니다. 병합할 때 `Squash and Merge` 을 사용합니다.

PR을 제출하기 전에 - `lint``typecheck` 및 `tests` 작업을 확인하십시오. 관련 없는 변경을 피하십시오.

즉시 검토할 것입니다. 관리자에게 할당되면 신중하게 검토할 것입니다. 빨간색 텍스트는 무시하십시오. 추적 목적으로 작성됩니다.
